01 / THE CORE CONFLICT

家长只补一笔差价
前台却要摆平三本账

在连锁儿童齿科，把 1–2 年短期卡补差价升级成 5 年长期卡是高频业务。但原门诊系统的会员卡、服务项目券与历史账单分属不同模块且毫无关联——前台在家长催促下跨页面翻找、按计算器手算补差，极易算错或漏停旧权益。

01. 当前会员卡状态

先核对原卡是否在有效期内，再根据业务允许的卡种对应关系，判断能否升级到目标长期卡。

最易遗漏断点

02. 割裂的服务与项目券

1–2 年短卡的涂氟等服务拆散在“卡内”和独立“项目券”中（5 年卡全在卡内）。升级时必须查清剩余服务，并手动按规则停用旧项目券。

03. 历史原始收费账单

已用服务不折算残值，补差严格按“原卡实付金额”计算。前台必须翻出当年开卡的原账单算差价，再分别处理新旧账单。

架构取舍：保留原系统底层，新建会员办理入口

重做底层收费会牵涉日常挂号与诊疗等大量核心业务，风险过高。团队决定保留原门诊系统，在内部新系统中集中组织规则与核对，通过接口调用原系统完成收退费与变更——这也决定了新流程必须妥善处理历史脏数据与接口中断。

02 / WORKFLOW ARCHITECTURE

把算账交给系统
为不确定与中断设计退路

顺着前台实际办理的思考节奏，从“确认现状与新卡”到“历史模糊账单甄别”，再到“接口中途报错后的无缝接手”。

01

先看现有权益，再同屏核对新购

把核对拆成相连的两步：工作台集中呈现患者身份、旧卡状态与剩余服务；点进升级弹窗后，同屏对比新卡权益、优惠与系统算好的应付补差，方便前台边核对边向家长解释。

02

历史账单模糊时，宁可停下让人工选

部分早期旧卡非新系统开通，回溯时可能抓出多笔同金额账单或查不到账单。选错会导致差价与退费全错，因此补充确定性分流：唯一账单自动算；多笔候选弹窗列出时间、医生与备注由前台勾选；无账单则阻断回原系统。

03

接口半途中断时，红绿进度单指引接手

跨系统接口连续执行退费与换卡时若遇超时中断，底层无法自动回滚。若只报笼统“失败”，前台不敢重试也不知卡在哪。我将反馈改为分步进度清单：已办妥的标绿保留，卡住的步骤标红，指引前台去原系统精准补完。

03 / FINANCIAL GOVERNANCE

用个人月度额度池
把风控锁在收钱之前

柜台前家长等不及审批，过去前台只能“先电话请示改价收银、事后补提审批”。我将优惠分类与授权机制彻底前置到交易发生的那一刻。

STEP 01 / BOUNDARY

剥离活动券与手动让价

  • • 公司活动优惠券：按活动门店/日期/卡种规则核销，不消耗个人额度。
  • • 现场手动优惠：前台谈单额外给出的让利，纳入个人月度额度池严格管控。
管控对象 仅限手动让价
STEP 02 / PRE-AUTH

按月度销售目标生成额度

  • • 店长按月录入员工销售目标，系统自动换算该员工当月可用的让价总额度。
  • • 额度内前台当场自主拍板，用完即止，无追加审批路径，彻底消灭事后补审批。
  • • 每笔优惠精确挂载至对应收费账单，供财务按人与门店随时核查。
授权方式 额度内当场拍板
STEP 03 / INTERACTION

确认报价瞬间实时锁死

方案通过一线宣讲与试用逐步推广至全连锁二十多家门店，允许员工在新旧办理入口间自主选择。首批试点多数反馈集中核对更方便，部分员工试用后逐渐养成日常习惯；也有少部分员工因习惯老系统操作觉得繁琐、使用较少（目前为一线定性反馈，未做强制一刀切与逐店采纳率统计）。

改造前的“约 4–5 分钟”来自前期一线调研中最熟练老员工的手工跨模块办理耗时；改造后的“约 1 分钟”来自新系统上线后典型升级场景的现场观察。由于原系统没有可用的埋点计时基础，此组数据为典型场景的现场实测观察对比，不代表全部复杂异常交易的平均值。

新系统已完整实现“个人月度额度内自主办理 + 超额实时拦截 + 每次使用挂载具体账单 + 财务按人/店查看消耗”的线上机制（暂未对审批等待时间或违规改价降幅做宏观统计归因）。同时，新系统仅约束从新入口发起的交易；若员工绕开新入口直接在原系统手动改价，仍需财务在日常核查中跟进。

作为轻量级业务层改造，日常挂号及其他诊疗收费依然留在原门诊系统，前台在日常工作中仍需在两套系统间衔接；此外，当遇到历史卡找不到原账单，或跨系统接口执行半途中断时，前台也需要根据界面标红提示回到原系统核对或继续处理完剩余步骤。
