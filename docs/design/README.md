# 设计资料归档

本目录用于归档项目的最终设计资料，重点保留可复用、可展示、可回溯的视觉材料。

这里不承担原始需求归档职责，也不替代 `docs/project/` 的项目事实文档，而是作为项目事实与网站展示之间的视觉证据层。

## 目录职责

- 归档各项目的最终设计资料。
- 保留可用于求职展示的关键界面图和少量必要的结构图。
- 记录设计稿来源链接、最终采用范围和简要说明。
- 为后续网站项目页提供可引用的视觉素材和设计说明。

## 与现有文档结构的关系

- `docs/origin/`：原始材料层，保存 PRD、会议记录、原始方案和需求依据。
- `docs/project/`：事实整理层，保存项目背景、问题、角色、方案、结果和原始依据。
- `docs/design/`：设计归档层，保存项目最终设计稿的链接、导出图和简要说明。
- `docs/site/`：网站提炼层，从 `docs/profile/`、`docs/project/` 和 `docs/design/` 中提炼页面内容与展示素材。

`docs/design/` 是辅助层，不改变当前 `origin -> project -> site` 的主整理顺序。

## 单项目推荐结构

每个项目建议使用如下结构：

```text
项目名/
  README.md
  final-screens/
```

## 文件说明

- `README.md`：作为单项目的总说明，直接写链接、归档范围、关键页面和可上站说明。
- `final-screens/`：存放最终采用稿的关键截图；如果确实有少量流程图，也可以先直接放在这里，不必再单独分目录。

## 归档规则

- 仅归档最终采用稿或已进入正式交付范围的方案。
- 不强求完整分类，优先保证“找得到、看得懂、能复用”。
- MasterGo 继续作为设计源头，仓库内优先保存“链接 + 关键导出图 + 简短说明”。
- 导出图片数量以“足够说明问题”为准，不追求全量留档。
- 若某个页面已有多个版本，仅保留最终采用版本，并在 `README.md` 中说明版本关系。

## 命名建议

- 文件夹使用项目名称，与 `docs/project/` 中的项目命名保持一致。
- 图片文件名统一使用 `序号-模块名`，例如 `01-读片主界面.png`、`02-AI判断卡片.png`。
- 避免使用 `最终版`、`最新版`、`终版2` 这类难以长期维护的命名方式。

## 使用建议

- 先完成 `docs/project/` 的事实整理，再补设计归档。
- 网站项目页优先从 `docs/project/` 提炼叙事，再从 `docs/design/` 选择对应视觉素材。
- 如果后续需要补充网站展示图，优先回到本目录选择素材，而不是重新四处查找设计稿。
- 当前阶段以轻量归档为主，不要求一次性补全所有说明。
