**“作者面对多卡种、卡券分离与高并发收银的真实泥潭，能够穿透表象抽象出系统的决策流水线，在工程约束中做出务实取舍，并画出降噪、易解释的高密度收银方案。”**

### 1.2 节奏与排版原则
- **不直接堆砌文本长段落**：把纯文本拆解为**现场快照、结构卡片、交互式逻辑流水线、界面深度图解与边界灰盒**。
- **高信噪比阅读动线**：
  `开场身份与职责` ➔ `现场高并发与三维矛盾` ➔ `系统决策流水线与额度机制` ➔ `收银台同屏信息架构图解` ➔ `严谨数据与工程妥协`。

### 模块 2：系统决策与机制重构（核心逻辑的可视化解构）
这是证明“作者能把规则理成系统”的最高含金量区域，采用**两组核心图解 + 一个对照组件**呈现：

#### 2.1 业务决策流水线（Decision Pipeline）
以横向连接的步骤流水线卡片展示，展现面对十几种卡时收敛出的 4 步标准化闭环：
1. `01 卡状态校验`：有效期与冻结状态确认；
2. `02 卡券穿透核算`：穿透历史账单，合并卡内项目与绑定的卡券剩余价值，自动计算净残值；
3. `03 目标卡匹配补差`：匹配年龄档位，计算差价并顺延有效期；
4. `04 额度规则校验`：匹配当月门诊/岗位额度，输出实付。

#### 2.2 自动与人工边界（Boundary Split View）
采用**左右双栏对比卡片**，呈现清晰的设计哲学：
- **左栏（标准路径 · 全自动）**：账单单一明确、卡状态正常 ➔ 系统自动计算与串联，前台一键确认即可执行。
- **右栏（异常场景 · 坚决停机）**：未检索到账单 / 存在多张历史账单需选择 / 卡冻结异常 ➔ **系统刚性中断盲目推算，弹出人工选择分支**。
- **设计推导注记**：“退卡补差动的是钱和权益，系统猜错的修复成本极高。宁可人工多点一次，绝不让系统替人盲猜。”

#### 2.3 优惠额度管理模型（Governance Flow）
对比**旧模式与新模式**的流转图：
- **旧模式**：钉钉发起 ➔ 嫌慢改电话确认 ➔ 现场直接改价 ➔ 事后补审批 ➔ 月底财务发现违规对不上账（监管真空）。
- **新模式**：事前配置门诊/岗位额度池 ➔ 额度内前台自主放权即时生效 ➔ 超额系统刚性阻断（流程中取消审批） ➔ 账单明细全量留痕可审计。

### 模块 3：收银台界面与信息降噪（图解式界面拆解）
证明“自己画得出方案”的主阵地，拒绝仅放一张无解释的冷冰冰截图，采用**深度标注走查（Annotated UI Walkthrough）**：

#### 3.1 同屏信息架构拆解（Three-Zone Walkthrough）
界面主图配合引线与区域高亮，拆解前台如何一屏看清所有信息：
- **Zone 1【原卡资产区】**：卡内项目残值 + 关联卡券剩余价值合并，解决旧流程中卡券分离、核对遗漏的问题；
- **Zone 2【目标卡权益区】**：清晰罗列升级后卡种的有效期顺延规则与新赠权益，方便向家长当场讲解；
- **Zone 3【差价计算区】**：直观展示“新卡标价 - 旧卡折抵 - 优惠额度 = 实付差额”，彻底免除现场心算。

#### 3.2 交互微策略（两项交互卡）
- **核对前移（Submit-Prevention）**：所有试算与额度规则在录入时即时联动警示，将争议遏制在点击提交之前。
- **渐进式暴露（Progressive Disclosure）**：常规路径保持极简；仅在多账单或超额时，就地展开异常诊断卡片，明确告知前台下一步怎么做。

---

### 模块 4：落地成效与现实边界（数据卡 + 诚实灰盒）
用克制、真实的排版建立极高专业信任感：

#### 4.1 数据与落地指标
- **落地规模**：先在 6 家门店试点，后推广至全连锁 20 多家门店。
- **操作耗时对比卡**：
  - 改造前：`4—5 分钟`（标灰，说明口径：调研中最熟练老员工平均时长，新手达十来分钟）；
  - 改造后：`约 1 分钟`（高亮强调，标明现场实测典型升级）。

#### 4.2 方案边界与工程妥协（两张现实灰盒卡）
- **妥协 1：外挂层带来的操作接续**：诚实写出挂号、诊疗仍保留在原门诊系统，前台仍需切换。点明这是“放弃重构整套收费系统、以最小成本快速推进外挂层”必然付出的操作代价。
- **妥协 2：失败回退的验证局限**：声明系统实现了原子回退与防悬空规则，但因上线平稳未发生端到端中断故障，故不虚构实测回退数据。
