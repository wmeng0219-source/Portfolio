# 正畸筛查与状态管理 · 设计规范 (Orthodontics Design Spec)

> **文档定位**：定义正畸深度案例的呈现顺序、视觉证据和交互重点。逐字文案见 [`content.md`](./content.md)；事实与指标见 [`docs/project/正畸筛查与状态管理.md`](../../project/正畸筛查与状态管理.md)；全局 UI 规范以根目录 [`DESIGN.md`](../../DESIGN.md) 为准。

## 一、页面呈现结构

按招聘者阅读顺序组织页面：

1. 一分钟摘要：问题、角色、判断、改变、结果边界；
2. 现场问题：重复筛选、临时患者遗漏、跨角色断点；
3. 策略演进：初版字段过重 → 单店试点 → 前端做减法；
4. 角色协作：护士、儿牙、正畸、运营的接力关系；
5. 三个关键判断：取消快筛、按发育窗口分流、削减儿牙字段；
6. 结果口径：同期成交转化率与上线至今累计漏斗分开展示；
7. 界面证据：状态机、任务看板、推荐优先级、资料有效期和异常状态。

## 二、视觉与交互重点

### 1. 首屏指标

- 使用 `System Mint #b9f2c8` 表示结果数字，使用中性底色承载口径说明。
- 首屏同时展示周期：`2025.02–04：30–40%` → `2026.02–04：50–60%`。
- “同期周期对比、非单项目因果结论”必须紧邻指标出现，避免数字被误读。

### 2. 流程与角色

- 主视觉锚点采用“状态轴 + 角色接力”组合：`未筛查 → 筛查中 → 待结论 → 需矫 → 推进中 → 已预约 → 完成`。
- 角色区块按真实责任顺序排列：护士 → 儿牙医生 → 正畸医生/总监 → 运营/业务。
- 角色卡只呈现任务和交接，不把“留痕”画成已验证的激励闭环。

### 3. 策略演进

- 用 Before / After 或横向步骤表现“前端收集更多字段”到“儿牙轻量筛查、正畸专业确认”的变化。
- 试点反馈属于设计判断证据，视觉上与正式业务结果分层，不使用同一结果色。

### 4. 推荐与状态

- 五级替牙优先级用编号或阶梯表达：恒牙列 → 剩余四颗乳牙 → 2-2 → 上 1 → 其余替牙期。
- 明确标注“运营调度优先级，不是医学风险等级”。
- 资料有效期用紧凑状态提示呈现：面相 6 个月；口扫/全景片 1 年；超期进入重新采集待办。
- 暂不干预、外院矫正、异常结束、早期矫正结束等状态用回流节点表现，不暗示其效果已被量化证明。

### 5. 结果模块

- 同期转化率使用双列对比；累计漏斗使用单独的数字流或漏斗图。
- 漏斗节点显示分子/分母，至少标注 `53.75% = 9,923 / 18,460` 与 `55.38% = 5,495 / 9,923`。
- 不使用“100%覆盖”“显著增长”“全流程闭环”等超出证据的标签。

## 三、设计系统约束

- 全局颜色、字体、圆角、间距和卡片描边严格继承根目录 [`DESIGN.md`](../../DESIGN.md)。
- 案例标题和结果使用 `System Mint`；行动和交互使用 `Digital Lavender`；案例标题装饰使用 `Soft Pink`，不引入第四强调色。
- 组件需要支持渐进式暴露：先显示状态和下一责任人，再展开推荐条件、资料有效期和异常原因。
