# 接诊全流程预习与任务编排引擎

## 我的角色与核心挑战

在这个项目中，我的核心角色是**产品设计师（Product Designer）**。由于该系统交互逻辑极其复杂，在设计过程中，我不仅负责了全链路的交互与视觉体验设计，还深度参与了产品逻辑的推演与重构。

**这是我第一次跨界撰写 PRD 文档**：在设计高密度信息展示和复杂的“任务包”交互时，我发现单纯的线框图无法穷尽诸如“伴随动作”、“牙位选择互斥”等边缘场景。因此，我主动承担了其中一份核心需求文档的撰写，通过设计推导倒逼产品逻辑的完善。

这个项目对我来说最大的挑战在于：**如何把极度复杂的底层业务逻辑（8大任务包、5套系统数据源、上百条流转规则），通过优雅、克制的交互界面呈现给一线医护，让他们用得爽而不是觉得在填表。**

## 项目背景

在儿童齿科接诊场景中，由于涉及初诊、复诊、特殊病史（多生牙、龋风险）、不同会员类型等复杂情况，患者就诊往往需要医生、护士、运营（前台/咨询）等多个角色紧密配合。

但在过去，接诊前的信息极度分散：家长诉求在网络电话系统、预约与收费在领健系统、既往病史和口腔检查表在患者360系统。这种信息孤岛导致门诊团队在患者到店前，难以形成统一的接诊目标，极其依赖人工沟通，容易出现漏项、沟通脱节或商业转化（续卡）机会的流失。

## 项目目标

- **打破信息孤岛**：提供统一的接诊前全景视图，让一线员工无需跨系统查阅。
- **接诊流程标准化**：将复杂的接诊过程拆解为结构化、可追踪的“任务包”。
- **强制多角色协同**：建立线上多方确认机制，确保患者到店前，医、护、运已对齐颗粒度。
- **降低一线负担**：通过前置编排，系统自动生成标准化的病历/接诊备注，减轻医生书写负担。

## 核心交互设计与体验重构

这个项目最难的地方，在于如何将极度复杂的“医疗逻辑与业务规则”转化为一线医护“看得懂、点得快”的界面操作。

### 1. 攻克极高密度的信息层级设计（最核心挑战）
整个预习流程中间的“任务编排区”是设计的重灾区。它的信息层级深得可怕，呈现出一种俄罗斯套娃式的结构：
**任务包 -> 具体任务 -> 任务内的多选/单选 -> 细化到单颗牙位的选择器**。

为了不让界面变成一张密密麻麻的电子表格，我做了以下体验重构：
- **卡片式折叠与展开**：将 8 大流程封装为 8 个任务包，支持拖拽排序、上下插入。初始化渲染时，若任务包内无任何动作则自动隐藏，极大减轻了首屏的视觉压迫感。
- **系统推荐与手动新增的视觉分离**：系统推荐的必做任务和手动新增的伴随任务在视觉和操作栏上做了清晰的优先级划分。
- **动态十字牙位选择器**：打破了传统的下拉框设计，专门为口腔场景定制了“十字牙位面板”，支持全口/象限框选，甚至能优雅地处理“23 近中多生牙”这种极小众的边界情况，并且联动患者的拔牙史动态展示。

### 2. “系统推导思维链”的优雅呈现
在任务包中，很多动作是系统根据底层海量规则自动推出来的（比如为什么系统突然推荐要做“龋风险评估”）。一线医护如果不理解系统为什么推，就会产生抗拒。
- **解法**：我没有把密密麻麻的底层逻辑直接怼在卡片上，而是设计了**“抽屉式的系统推荐理由（思维链）”**。
- **体验**：在任务条最右侧保留一个小小的“破折号”入口。点击后，右侧会滑出一个抽屉，清晰地展示系统推导出这个任务的“思维链”（比如：因为患者上一次就诊查出了某某问题 + 距离今天已过半年 = 触发本次检查）。这种**“默认隐藏复杂，按需展示逻辑”**的设计，既保证了主流程的清爽，又让系统具备了极高的“可解释性”。

### 3. 多角色防卡点与时效性防呆
- **必填项的视觉动线引导**：每个角色（医、护、运）都有对应的专属必填项。当点击【预习下一个】流转失败时，系统不仅进行强阻断，还会自动定位滚动到首个未完成的必填项，并将输入框标红提示，避免用户在长页面中迷失。
- **7天过期重置确认**：考虑到患者情况随时会变，若本次距离上次预习间隔超 7 天，系统会弹出强制确认窗。这个简单的阻断设计，有效防止了团队拿着过期的预习方案去接诊。
