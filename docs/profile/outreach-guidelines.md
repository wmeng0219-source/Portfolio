# 打招呼与 Outreach 话术规则

> 适用：BOSS 直聘首次打招呼、投递邮件正文、猎头/内推私信。
> 来源：2026-10-28 用户逐轮确认（共 5 轮修订）。用户再次提出新规则时，追加到本文并标注日期。

## 硬规则

1. **不迎合 JD，按真实背景写。** 不写「高度匹配」「职责重合」「非常契合」这类对齐句；不为了贴合 JD 编造行业、年限或职责。判断依据是 `career-timeline.md` 与 `domain-and-strengths.md`。
2. **可以贴近，但要贴得诚实。** 从 JD 反推对方真实需要什么（通常写在职责里，而不是写在「优先」里），用自己真实做过的事去对应；对方没有的东西不硬蹭。
3. **不强调「转型」。** 不写「近两年转产品」「从设计转过来」「名义上是设计岗」这类句式。打招呼阶段解释岗位名，等于提前自我辩护。
4. **不解释身份、不铺细节。** 首条消息只交代三件事：在哪、做过什么、想做什么。规则细节、身份差异、项目拆解留给第二轮。
5. **真诚、少 AI 味。** 去掉形容词堆砌和排比；用一个真实的具体对象（系统名、业务环节）代替能力描述；允许口语短句。
6. **留一个记忆点。** 一句自己的判断或体感（例：「门店规则碎、角色多」），比罗列履历更容易被记住。
7. **目的只有一个：让对方愿意收简历。** 结尾用「想投份简历给您看看，方便吗？」，不用「聊聊」（前者成本更低）。

## 术语与事实边界

- **二轮再讲 BRD / PRD / UAT / 里程碑**：首条消息堆术语像背 JD 答案。
- **不写「4 年以上 BA/PM」**：实际 3 年半（2023.04–2026.09），写出来等于给对方一个筛选理由。
- **不主动提「服装零售」等未经历行业**；连锁多门店是同构点，用业务对象（收银、会员、预约）体现，不用行业词包装。
- **设计背景可以出现，但不作解释性说明**，仅作为事实一带而过或干脆不出现。

## 已确认可用的基准版本

> 您好，我在极橙医疗做了三年多连锁门店的数字化，主要处在业务和 IT 之间：到门店听需求，把零散的说法整理成能开发的方案，再跟排期推到上线。收银会员、预约、正畸筛查这几套系统都参与过；门店端规则碎、角色多，这几年主要在处理这些。想投份简历给您看看，方便吗？

- 长度约 110 字，手机通知栏不易折叠。
- 结构：位置（业务与 IT 之间）→ 动作（听需求、整理方案、推到上线）→ 具体对象 → 体感记忆点 → 低门槛请求。

## 按岗位微调的接口

只允许替换三处，其余保持不动：

1. **具体对象**：换成与对方业务同构的系统名（例：门店运营、订单、结算、会员）。
2. **记忆点句**：换成自己对该类业务的真实判断，不虚构。
3. **行业锚点**：对方若明显看重某场景，可在首句点出同构词（连锁、多门店、一线员工在用），不改行业名。

## 维护

- 新增规则时保留原文与日期，不覆盖旧结论。
- 与 `overview.md` 的求职定位（产品经理 + UI/UX 背景，不限行业）冲突时，以本文的沟通口径为准，事实以时间线为准。
