# 过程文档归档

本目录用于保存 AI 协作过程中产生的规格文档、实现计划和阶段性方案。

这些文档的价值在于记录“方案为什么这样形成、过程中试过哪些路径、最终为什么收敛到现在的页面”，而不是直接充当当前页面内容的事实来源。

## 目录结构

- `specs/`：设计规格、边界定义和方向说明。
- `plans/`：实现计划、任务拆分和执行步骤。

每一层再分为两类：

- `current/`：对当前站点仍有解释价值的文档。
- `archive/`：历史过程、试验方案或已被后续版本替代的文档。

## 当前保留逻辑

### `current/` 保留什么

- 仍能解释当前站点结构和内容分层的文档。
- 与当前首页最终实现直接对应的方案文档。
- 作为后续维护仍可能回看的阶段性基线文档。

当前主要包括两类内容：

- 文档与站点结构基线：
  - 三层文档结构
  - 定位与内容整理原则
  - 站点内容结构
- 当前首页最终方案：
  - `Hero + Portfolio` 的 `GSAP Brand Stage`
  - `About + Experience + Contact` 的 `System Showcase`

### `archive/` 归档什么

- 已被后续方案覆盖的中间版本。
- 当时有效、但已不再对应当前页面结构的试验性方案。
- 已完成历史使命的早期组织和实现文档。

## 适合什么时候看

### 想回看当前版本是怎么定下来的

优先看 `current/`，尤其是同一天的 `spec + plan` 配对文档。

### 想追溯某一轮尝试或废弃路径

查看 `archive/`，那里保留了中间迭代和已过期方案。

### 想知道页面现在该以什么为准

不要优先看这里，应按以下顺序查看：

1. 当前页面实现
2. `docs/site/`
3. `docs/profile/` 和 `docs/project/`

## 当前使用原则

- 已经整合进页面的内容，以当前实现和 `docs/site/` 映射为准。
- 若过程文档与当前页面不一致，优先相信当前实现，再决定是否补更新说明。
- 本目录不承担长期资料维护职责，不直接作为网页文案来源。
- 后续若新增大改版，可以继续保留过程文档，但应及时判断其进入 `current/` 还是 `archive/`。
