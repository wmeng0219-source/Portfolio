```md
## 项目背景

在儿童齿科接诊场景中，患者到店前往往需要医生、护士、运营等多个角色提前协同。但原有信息分散在多个系统中，团队很难在接诊前形成统一目标，流程高度依赖人工沟通，容易出现漏项、协作脱节和转化机会流失。

## 项目目标

- 打破信息孤岛，建立统一的接诊前全景视图。
- 将复杂接诊过程拆解为结构化、可追踪的任务包。
- 让医、护、运协同从线下补位转为系统承接。
- 通过前置编排降低一线执行负担。

## 我的角色

我在该项目中的主身份是产品设计师，负责全链路的交互与体验设计。但随着方案推进，我的工作边界逐步延伸到产品逻辑推演与规则收束：在高密度任务编排和复杂边界场景中，单纯线框图已不足以覆盖真实问题，因此我进一步参与需求文档撰写，通过设计推导反向推动产品方案成形。
```

要求：

- 主身份必须保持为“产品设计师”。
- 但要明确体现“设计驱动产品”的路径，而不是只写视觉与交互工作。

- [ ] **步骤 4：重写“核心问题 / 关键方案”**

将中段内容收束为问题与方案对应关系：

```md
## 核心问题

- 接诊前信息分散在多套系统中，团队缺少统一视图。
- 多角色协同依赖人工沟通，缺少线上承接机制。
- 任务包层级深、规则多，传统界面形式难以让一线快速执行。
- 系统推荐动作若不可解释，容易引发一线抗拒和执行偏差。

## 关键方案

### 任务编排界面

将复杂接诊流程封装为可排序、可折叠的任务包，并通过卡片结构、隐藏空任务包和牙位选择器等设计，承接高密度信息与复杂操作。

### 系统推荐理由可解释化

通过抽屉式的系统推荐理由展示，让一线在主流程保持清爽的同时，按需查看系统如何推导出任务建议，提升系统可解释性。

### 多角色流转与防卡点机制

围绕医、护、运不同角色的必填项、流转阻断和时效校验，建立更清晰的线上推进路径，减少长页面操作中的遗漏和过期执行。
```

要求：

- 每个小节都要写“原问题 -> 方案如何承接 -> 为什么这不仅是界面设计”。
- 不保留过多“这个交互很优雅”式复盘语言。

```md
该项目的推进难点不在单一页面设计，而在于复杂规则需要被逐步收束为可执行方案。随着设计深入，我开始通过需求文档和规则推演补齐线框图无法覆盖的边界场景，使方案从“界面草图”转向“可讨论、可确认、可落地”的产品方案。

## 项目结果

- 建立了统一的接诊前预习视图与任务编排结构。
- 将复杂接诊流程转为系统可承接的任务包机制。
- 为医、护、运协同建立了更明确的线上推进路径。
- 验证了我从产品设计深入到产品逻辑和规则整理的能力。

```

要求：
