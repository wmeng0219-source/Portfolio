# 首页人物封面与章节滚动重构设计

## 概述

本次设计不是继续往当前首页里叠加动画，而是在保留整体“人物登场 + 能力信号 + 主线篇章”方向的前提下，重新整理首页第一屏与滚动阅读节奏。

当前版本的主要问题不在于内容缺失，而在于：

- `Hero` 仍然承担了过多叙事任务，左侧正文、右侧说明面板与动作按钮同时争抢首屏注意力
- 中文标题与正文的容器宽度、字距和行长控制偏紧，导致多处换行不自然
- 区块滚动虽已接入 `GSAP`，但大部分区块仍使用相近的 reveal 逻辑，缺少章节推进感
- 页面整体更像“带动画的模块列表”，还没有真正建立出接近参考网站的连续阅读体验

本次确认采用的方向为：

- `A：人物封面 + 章节滚动`

目标是在不牺牲职业可信度的前提下，让首页更接近你偏好的参考气质：更安静的首屏、更清晰的中文阅读节奏、更明显但克制的滚动层次。

## 设计目标

### 目标 1：让首屏先建立人物识别，再解释工作方式

`Hero` 的第一任务应是建立“你是谁”的识别，而不是在首屏同时完成自我介绍、方法说明和章节预告。

因此新的 `Hero` 需要：

- 保留名字和角色作为视觉中心
- 把正文压缩为一段短说明
- 保留双 CTA，但降低其视觉抢占程度
- 把右侧面板从“第二块正文”降级为“章节预告”

### 目标 2：修正中文排版中的拥挤与断裂感

当前页面多个标题与正文都使用了偏激进的宽度和字距策略，英文语境下仍可接受，但中文阅读里更容易形成：

- 一句被切成过多短行
- 标题断句位置不自然
- 说明文字显得局促、喘不过气

本次需要重新建立更适合中文的：

- 标题宽度
- 行长控制
- 行高
- 字距

### 目标 3：让滚动更像章节推进，而不是统一淡入

当前 reveal 的问题不是“没有动”，而是“各区块动得太像”。页面缺少：

- 首屏与后续区块之间的强弱差异
- 第二幕被唤醒的进入感
- 主篇章优先到达的滚动顺序

本次需要让滚动承担叙事功能：它要帮助用户感知首页结构，而不是只是增加动态感。

## 设计读取

Reading this as: 面向招聘方与协作方的个人作品集首页，需要更强的编辑感人物开场与章节推进节奏，视觉语言参考 `trionn.com` 与 `ten.375.studio` 的克制叙事风格，但输出仍然服务于职业可信度与真实能力表达。

建议页面参数如下：

- `DESIGN_VARIANCE: 7`
- `MOTION_INTENSITY: 7`
- `VISUAL_DENSITY: 3`

含义如下：

- 页面有更明显的版式落差和节奏变化，但不进入实验性结构
- 动效比当前更明确，但仍以层次、进入、轻视差为主，不做重度滚动劫持
- 信息密度整体下调，优先给人物识别与章节阅读让位

## 当前问题诊断

### 1. Hero 过满

当前 `Hero` 的问题不是元素太多，而是“都在首屏里承担主角职责”：

- 名字是大视觉中心
- 角色标题也是高权重标题
- 正文长度仍在解释工作方式
- 右侧 `panel` 又承担了一次章节说明
- CTA 和 `meta strip` 仍在第一屏参与竞争

结果是首屏虽然已经比旧版更好，但还没有真正形成“人物封面”。它更像“排得不错的信息页头”。

### 2. 中文换行不自然

以下排版策略在当前版本里会共同放大中文换行问题：

- 多个标题使用较窄的 `max-width`
- 标题和角色文字使用较紧的负字距
- 不同模块沿用相似的英文式标题宽度控制
- 正文列宽偏窄，导致句子早换行

这些问题叠加后，会让中文产生“被盒子挤碎”的阅读感。

### 3. 页面滚动强度不够区分

当前首页已有：

- `Hero` 首屏入场
- 区块 reveal
- hover 微交互

但滚动语言仍然偏统一，主要问题包括：

- 多数区块 reveal 参数接近，叙事强弱差异不足
- `ProofStrip` 作为第二幕没有更鲜明的唤醒感
- `Portfolio` 虽有主次结构，但滚动到达时没有真正形成“主篇章先出现”的体验
- 动效存在，但阅读顺序没有被强化

## 方案比较

### 方案 A：人物封面 + 章节滚动（推荐）

特点：

- 进一步压缩 `Hero` 的信息密度
- 右侧面板降级为更轻的章节预告
- 通过分区块滚动强度差异建立章节推进感

优点：

- 能同时解决拥挤、换行和滚动三个问题
- 与当前首页方向连续，不是推倒重来
- 最接近你给的参考网站气质

缺点：

- 需要同步调整文案承载方式、模块节奏和动效参数
- 改动面比“只加动画”更大

### 方案 B：首屏排版重做，滚动仅轻修

特点：

- 重点解决 `Hero` 与文字换行
- 保留大部分现有 reveal 机制，只做参数微调

优点：

- 风险较低
- 能较快让首页更干净

缺点：

- 页面滚动层次提升有限
- 无法真正形成章节推进感

### 方案 C：保留首屏结构，强化动效叙事

特点：

- 不大动 `Hero` 信息结构
- 主要提升滚动层级和章节入场

优点：

- 实现成本最低
- 可以快速增强页面动态感

缺点：

- 首屏拥挤和中文断行问题仍会保留
- 更像修饰，不像重构

## 推荐方案

采用 `方案 A：人物封面 + 章节滚动`。

该方案的核心不是继续添加元素，而是降低首屏噪音、修正中文阅读姿态，并让动效真正承担结构表达职责。

新的阅读顺序应变为：

1. 先看见 `Meng Wen`
2. 再确认“产品设计师与数字化实践者”
3. 再读一段非常短的工作方式说明
4. 滚动后进入“第二幕 / 能力信号”
5. 再进入主线篇章与侧篇章

## 页面结构设计

### 1. Hero：从信息页头改为人物封面

`Hero` 需要回到“封面”的职责，而不是继续承载过多说明。

建议结构：

- 左侧：`Act One`、名字、角色、一段说明、两个 CTA
- 右侧：轻量章节预告块

`Hero` 的文本层级严格限制为四层：

1. 小型章节标记
2. 名字
3. 角色
4. 一段说明

说明文字要明显短于当前版本，职责是解释你的工作方式，不是复述整页叙事。

CTA 仍保留：

- `查看案例`
- `联系我`

但它们应退居为动作层，不应继续参与首屏视觉中心竞争。

### 2. Hero 右侧章节预告

右侧区域不再承担完整说明职责，不再像第二块正文卡片。

新的角色应是：

- 作为章节预告和气氛建立
- 提示接下来会进入方法、能力与代表项目
- 以更少文本、更强留白和更轻层次参与首屏

可保留：

- `Episode`
- `01`
- 一句简短的章节引导语

应弱化：

- 过长的说明正文
- 再次重复价值主张的长句

它的存在感应低于左侧人物信息，不再成为首屏的第二叙事中心。

### 3. 中文排版与换行策略

本次会把中文阅读节奏作为单独设计层处理，而不是顺手在 CSS 里微调。

#### Hero

- 名字继续承担大字号，但保留更充足的呼吸空间
- 角色标题放宽宽度限制，避免被切成过碎的两三段
- 说明正文放宽列宽，减少中文被过早换行
- 标题与角色的负字距减弱，避免中文紧贴

#### 章节标题

- `ProofStrip`、`Portfolio` 等区块标题不再统一使用同一套偏窄宽度
- 中文标题优先按自然语义断句，而不是按英文封面式窄栏硬切
- 段落行长控制回到更舒适的中文阅读区间

#### 全页原则

- 中文主标题不追求极限紧凑
- 同一页中的标题宽度策略按模块职责区分
- 通过宽度、行高和留白建立节奏，而不是依赖过强的负字距

### 4. ProofStrip：作为真正的第二幕出现

`ProofStrip` 当前已经是“第二幕 / 能力信号”，但进入感还不够鲜明。

本次会强化它的角色：

- 滚动到达时形成一次明确的章节唤醒
- 标题与卡片之间建立更强的前后关系
- 让它看起来像“从人物进入能力说明”，而不是普通下一屏

表达方式仍保持克制，不做夸张位移，但要让用户明显感到页面进入下一幕。

### 5. Portfolio：突出主篇章到达感

`Portfolio` 已经具备主次结构，但当前滚动到达时主次关系还不够强。

本次会强调：

- 主篇章先进入阅读中心
- 侧篇章作为补充在后续接上
- 标题区、主卡、侧卡在滚动到达时有更明确的先后感

目标不是做复杂特效，而是让用户更自然地先读到主线，再理解侧线。

## 动效设计

### 动效原则

本次动效不以“更多”为目标，而以“更有叙事职责”为目标。

所有新增或调整动效都应满足以下用途之一：

- 建立层级
- 建立章节切换
- 强化阅读顺序
- 提供轻量交互反馈

不引入以下方向：

- 重度滚动劫持
- 大幅横向滚动叙事
- 夸张位移和长距离飞入
- 高频循环特效

### Hero 动效

`Hero` 继续使用首屏自动入场，但层级需要拉开：

- 名字先成为视觉中心
- 角色随后进入
- 正文和 CTA 再补齐信息
- 右侧章节预告最后到位

视觉上应像“人物登场”，而不是所有元素一组淡入。

### 区块滚动

`useHomepageMotion()` 不再把所有区块视为同一 reveal 类型。

需要建立至少三类动效强度：

1. 普通章节进入
2. `ProofStrip` 的章节唤醒
3. `Portfolio` 的主篇章优先到达

这样首页滚动时才会出现轻微但明确的叙事节奏差。

### 轻视差与 hover

当前 hover 微交互可以保留，但只作为辅助。

允许继续使用：

- 按钮轻微上浮
- 卡片轻微抬升
- `Hero` 右侧视觉块的轻度视差

但所有 hover 与视差都应服务于“高级感与层次”，不能盖过阅读本身。

### Reduced Motion

继续保留 `prefers-reduced-motion` 降级。

在降级模式下：

- 取消连续漂浮与视差
- reveal 退化为即时出现或极短时长过渡
- 保持阅读顺序，但不制造动态负担

## 视觉语言建议

### 氛围

氛围延续当前深色、冷感、克制的基底，但会进一步减少“首屏里每样都很满”的状态。

重点不在于增加更多材质，而在于：

- 让主要信息更少
- 让留白更有效
- 让视觉中心更单一

### 卡片感

当前部分区块的“卡片存在感”略强，容易让页面继续读成模块堆叠。

本次方向会适度削弱卡片感：

- 保留边界
- 减弱同质化的盒子感
- 通过节奏、留白、标题顺序来建立层次

### 章节感

章节感将主要通过三件事建立：

- 小型章节标记
- 区块到达顺序
- 动效强弱差异

而不是靠大量装饰标签或过强的视觉技巧。

## 边界

### 本次设计会覆盖的内容

- `Hero` 信息层级与布局重构
- `Hero` 右侧章节预告减重
- 中文标题与正文断行策略调整
- `ProofStrip` 与 `Portfolio` 的滚动节奏增强
- 首页区块阅读顺序的层次强化

### 本次设计不会直接决定的内容

- 项目案例页的二级结构
- 大规模重写中英文文案语义
- 引入新的重型滚动框架
- 改变首页现有主导航信息架构

## 第一阶段优先级

如果进入实现，建议按以下优先级执行：

1. `Hero` 结构与排版减负
2. 中文标题与正文换行规则校正
3. `useHomepageMotion()` 的章节强弱重构
4. `ProofStrip` 与 `Portfolio` 的进入节奏调整

原因如下：

- `Hero` 和中文换行是当前观感问题的根源
- 动效需要建立在更清晰的版式之上
- 先减负，再加层次，结果会更稳定

## 验收标准

完成后应满足以下条件：

- 首页首屏在不滚动时，视觉中心明确落在人物信息上
- `Hero` 不再显得拥挤，右侧内容不再与左侧争抢叙事主导权
- 中文标题和正文换行显得自然，不再有明显被窄栏硬切的感觉
- 滚动时能明显感受到“人物登场 -> 能力信号 -> 主线篇章”的推进关系
- 动效存在感增强，但页面仍保持专业、克制、可信的整体气质
