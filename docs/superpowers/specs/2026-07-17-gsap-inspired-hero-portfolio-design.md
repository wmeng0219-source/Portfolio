# 参考 `gsap.com` 优化 Hero 与 Portfolio 设计

## 概述

本次设计只处理首页中的两个区块：

- `Hero`
- `Portfolio`

目标不是模仿 `gsap.com` 的品牌内容或信息结构，而是参考它的两类能力：

- 动效语言
- 版式与层级控制

本次方向已经明确限定为“中等强化”：

- 不做激进的 showcase 化改造
- 不把页面做成纯动画演示站
- 不改变当前作品集的内容导向

需要借鉴的是 `gsap.com` 那种更强的舞台感、秩序感、节奏控制和品牌级页面气质。

## 设计目标

### 目标 1：让 Hero 更像品牌首页入口，而不是内容模块首屏

当前 `Hero` 已经具备较强的暗色氛围和几何信号，但视觉主角仍不够集中。

本次需要让 `Hero` 更接近高质量品牌站的首屏体验：

- 主标题成为唯一绝对主角
- 正文和 CTA 收敛到辅助层
- 顶部信息与背景装置不再抢主视觉
- 动效顺序更明确，避免多个元素同时争夺注意力

### 目标 2：让 Portfolio 更像精选陈列，而不是三个并排信息卡

当前 `Portfolio` 已经完成三卡并列结构，但整体仍偏“组件集合”。

本次需要强化它的品牌陈列感：

- section 自身先形成舞台
- 三张卡片建立清晰阅读顺序
- hover 反馈更精确、更克制
- 文本层级更像“精选案例入口”，而不是信息说明板

### 目标 3：统一 Hero 与 Portfolio 的动效语言

`gsap.com` 值得借鉴的核心不是“元素很多”，而是“少元素、强秩序、清晰时序”。

因此这次要统一 `Hero + Portfolio` 的动效语言：

- 入场顺序一致
- 缓动风格一致
- 背景持续动画降噪
- hover 反馈统一为更精确的品牌站节奏

## 当前问题

### Hero 当前问题

当前 `Hero` 的主要问题不在于元素不够，而在于主次关系仍偏平均：

- 顶部信息、几何装置、ticker、右侧圆环都具备较强存在感
- 主标题虽大，但还没有形成“唯一视觉支点”
- CTA 的存在正确，但与整体舞台层级还没有完全拉开
- 持续动画数量略多，使首屏有一种“整体都在动”的感觉

这会削弱高质量品牌站常见的“先看主标题，再看说明，再进入操作”的清晰阅读路径。

### Portfolio 当前问题

当前 `Portfolio` 的主要问题是已经整洁，但节奏还不够强：

- section 标题区和卡片区衔接过于直接
- 三张卡并列是对的，但没有形成浏览顺序
- hover 仍偏卡片组件思路，而不是品牌陈列思路
- 每张卡内部的信息密度略高，视觉重心不够收敛

结果是“结构没问题，但气质还没完全升级”。

## 参考对象提炼

### 从 `gsap.com` 借鉴的不是样式表象，而是页面控制能力

本次明确借鉴以下特征：

- 极薄导航与大面积留白形成舞台感
- 大标题占据主导，其他元素全部降级
- 背景和装饰不是主角，只服务于主标题的张力
- CTA 数量极少，权重明确
- 通过分层 reveal、轻视差和精准 hover 建立高级感

### 明确不借鉴的内容

- 不照搬 `gsap.com` 的绿色品牌色
- 不使用其品牌文案、内容结构和产品导向
- 不把首页变成插件展示或工具导航页
- 不做重型 pinned storytelling

## 设计决定

### 决定 1：Hero 保持现有信息结构，但重做主次层级

`Hero` 不重写信息内容，只重做层级关系。

保留：

- 顶部信息条
- 双行主标题
- 正文说明
- 单一主 CTA
- 底部 ticker

但重新定义它们的权重：

- 主标题是唯一一级视觉元素
- 正文与 CTA 是二级元素
- 顶部信息条和 ticker 是三级元素
- 几何装置与背景只作为舞台层

### 决定 2：Hero 的背景装置改为“远景舞台”而不是“并列主角”

当前右侧几何图形与 trailing circle 的设计方向是对的，但存在感略强。

本次调整原则：

- 几何装置保留，但整体更远、更淡、更慢
- 降低持续旋转的感知强度
- 重点保留轻微视差，而不是高存在感装饰
- trailing circle 只保留为远景信号，不再成为局部视觉焦点

这样可以让页面更接近品牌首页的“舞台背景”而不是“装饰物陈列”。

### 决定 3：ticker 保留，但降级为品牌底噪

ticker 是当前 `Hero` 中一个有效的品牌化元素，因此不删除。

但要重新定义它的职责：

- 不承担主要阅读内容
- 速度更慢
- 对比度更低
- 字号与边界处理更轻

它应像品牌氛围层，而不是一个需要用户主动阅读的模块。

### 决定 4：Portfolio 增加 section 舞台感，再进入三卡

`Portfolio` 保持三卡并列结构，但 section 本身要先成立。

调整方向：

- 标题区和简介区先形成更完整的 section statement
- 标题区与卡片区之间拉开更清晰的呼吸
- 让卡片在视觉上像“精选陈列的下一步”，而不是直接开始列组件

### 决定 5：Portfolio 三卡要建立阅读顺序，而不是完全等权

虽然三张卡仍并列，但需要通过版式和动效建立顺序：

- 从左到右的 reveal 节奏更清晰
- 第一张卡默认成为阅读起点
- 第二、三张卡通过轻微延迟和局部节奏形成跟随

这不意味着做主次布局，而是在并列结构中建立浏览顺序。

### 决定 6：Portfolio hover 改成品牌站式精细联动

当前 hover 的基础方向是正确的，但还可以更克制。

本次 hover 语言统一为：

- 卡片整体轻微上移
- 边框亮度提升
- 标题提亮
- 箭头轻位移
- 局部光感放大但不夸张

不再强调：

- 大幅漂浮感
- 过强发光
- 过度组件化交互语义

### 决定 7：动效统一采用更干净的品牌级节奏

本次 `Hero + Portfolio` 的动效需要统一语言。

统一原则：

- 入场顺序：框架 -> 标题 -> 正文 -> CTA / 卡片
- 缓动以 `power2.out`、`power3.out`、线性微动为主
- 减少看起来“Q 弹”的反馈
- 持续动画只保留极少数背景级信号

## 组件级设计

### Hero 组件

涉及文件：

- `src/components/Hero/index.jsx`
- `src/components/Hero/Hero.module.css`

设计要求：

- 保留当前文案结构与锚点行为
- 标题尺寸、行高、占屏比例进一步放大
- 正文最大宽度收紧，使阅读列更像品牌站文案模块
- 顶部信息条颜色与存在感下调
- 几何装置改为更克制的远景背景
- ticker 降低对比度与速度感
- CTA hover 调整为更精确的位移与箭头反馈

### Portfolio 组件

涉及文件：

- `src/components/Portfolio/index.jsx`
- `src/styles/global.css`

设计要求：

- 保持三卡结构和当前数据映射方式
- section 标题区与卡片区之间建立更明显呼吸
- 卡片的标题、摘要、metric 三层级更清晰
- hover 联动更精细但不过度
- 通过 reveal 顺序建立浏览路径

## 动效设计

### Hero 动效

保留并优化：

- 主标题分层进入
- 背景装置轻视差
- 微弱远景呼吸
- ticker 持续平移

调整重点：

- 降低背景装置持续旋转的存在感
- 让标题入场更“先发生”
- CTA 晚于正文出现，形成节奏终点

### Portfolio 动效

保留并优化：

- section heading reveal
- 三卡逐张淡入上移
- hover 联动反馈

调整重点：

- 卡片 reveal 的时间差更明确
- 卡片 hover 位移更小、更精确
- 去掉任何会让案例区显得“玩具化”的多余反馈

## 数据与工程边界

### 保持不变

- 继续使用 `src/locales/*.json` 作为文案来源
- 继续使用 `src/data/projects.js` 作为项目事实来源
- 继续使用现有详情页路由
- 继续使用 GSAP，不引入新的动画库

### 允许调整

- 允许新增或微调少量 locale 字段，用于优化 `Hero` 或 `Portfolio` 的展示文案
- 允许重组组件内部 DOM 结构
- 允许调整 `useHomepageMotion` 的节奏参数，使其与新的设计层级一致

## 非目标

本次明确不做以下内容：

- 不改 `About`、`Experience`、`Contact`
- 不重做导航系统
- 不改项目详情页结构
- 不做横向滚动案例区
- 不做重型 pinned section
- 不引入品牌色改造
- 不把网站改成纯 showcase 风格

## 验证标准

### 视觉标准

- `Hero` 首屏必须形成更强的单主角视觉中心
- `Hero` 的装饰层不再与标题争抢权重
- `Portfolio` 区块要更像精选案例陈列，而不是普通信息卡列表
- `Hero + Portfolio` 的版式、间距、对比度和层级语言需要统一

### 交互标准

- 主 CTA 与案例卡片跳转保持正常
- 动效顺序可感知，且不会显得杂乱
- hover 反馈更精确、更克制
- `prefers-reduced-motion` 下仍保持可读和可用

### 工程标准

- 不引入新的动画依赖
- 不破坏当前多语言与数据映射机制
- 不破坏 `npm test` 与 `npm run build`

## 范围判断

本规格只覆盖 `Hero + Portfolio`，范围明确且足够聚焦，可以直接进入实现计划阶段，不需要继续拆分为多个子项目。
