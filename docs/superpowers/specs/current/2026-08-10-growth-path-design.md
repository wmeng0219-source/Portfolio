# 首页成长路径设计规格

## 目标

将首页原本容易被理解为匿名工作履历的 Experience 模块，重构为明确的角色与能力成长路径。模块不展示公司和年份，而是解释解决问题的边界如何从界面执行逐步扩展到系统落地。

## 信息结构

- 模块名称使用「成长路径 / Growth Path」。
- 标题为「从界面执行，到系统落地」。
- 引言强调成长来自问题边界扩大，而不是岗位名称变化。
- 四个阶段依次为：界面设计者、复杂系统设计者、产品方案参与者、业务与交付连接者。
- 每阶段包含阶段编号、角色名称、能力动作和简短说明，不包含年份、公司或职位履历。

## 视觉结构

- 保留首页暗色演示文稿风格，不引入新的色彩或卡片体系。
- 桌面端使用连续纵向路径：左侧阶段编号与连接轨道，右侧为角色和说明。
- 当前阶段使用薰衣草紫节点突出，前三阶段使用克制的发丝线和中性色。
- 移动端收敛为单栏路径，保持连接关系和快速扫读能力。

## 页面关系

导航名称同步由「经历 / Experience」改为「成长 / Growth」。模块仍使用 `#experience` 锚点，避免破坏现有滚动定位逻辑。About 解释工作方法，Growth Path 解释角色演进，两者文案不重复。

## 验收标准

- 首页不再展示成长阶段年份。
- 中英文界面均明确使用 Growth Path 语义。
- 四阶段角色名称与能力说明完整呈现。
- 桌面和移动端均能读出一条连续演进路径。
- 首页动效、锚点导航和其余模块保持正常。
