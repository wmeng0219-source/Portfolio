# 作品集内容就绪度文档设计

## 目标

让现有项目事实库能稳定产出可信、可读且符合“具有设计背景的复杂业务系统产品经理”定位的案例，而不通过补写文案掩盖证据缺口。

## 设计

案例规范负责定义证据标准；项目目录新增就绪度清单，逐项目记录资料强项与待补材料；站点内容映射规定首页、详情页与扩展案例的取材边界；个人资料目录负责沉淀角色可信度和跨行业能力映射。

## 不在范围内

- 不改动页面、组件、数据结构或视觉规范。
- 不新增、修改或推断业务数据、个人职责、研究结论和项目结果。
- 不改变三个首页主案例与一个候选案例的当前排序。

## 验收标准

- 每一类内容缺口都有唯一的维护归属与回填路径。
- 四个项目都能看出当前可用证据与进入页面前仍需补的证据。
- 待补项不会被误读为已发生事实。
- 所有页面相关表达继续以根目录 `DESIGN.md` 为视觉唯一依据。
