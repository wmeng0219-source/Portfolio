# 首页框架重构设计

## 概述

本次设计聚焦于首页整体框架重构，目标不是单纯“美化页面”，而是把当前偏平的单页结构，调整为更有判断力、更有设计张力的作品集首页。

本次确认采用的方向为：

- `C：叙事首屏 + 能力证据 + 项目入口`

页面整体气质保持专业、克制、清晰，但在首屏和项目区增加更强的视觉结构与节奏变化，使页面从“内容模块的排列”升级为“带有叙事推进的首页”。

## 当前问题

当前页面已有较清晰的内容基础，但设计冲击力不足，主要问题不在内容本身，而在结构与视觉组织方式：

- `Hero` 目前更像自我介绍页头，缺少能够承载专业感的结构化主视觉
- `About`、`Experience`、`Portfolio` 在版式上过于相似，页面节奏较平
- `Portfolio` 目前仍接近“方向列表”，不足以形成作品入口的舞台感
- 页面信息层级以模块并列为主，缺少“先建立判断，再给出证据，再展开案例”的递进逻辑
- 现有紫蓝渐变氛围较强，但不完全贴合“复杂业务产品设计”所需的高级感和可信度

## 设计目标

### 目标 1：强化首页第一印象

首页第一屏需要快速传达：

- 你是谁
- 你擅长处理什么问题
- 你如何工作

而不是只停留在名字、身份和一句简介。

### 目标 2：建立更清晰的叙事顺序

首页内容顺序应从并列模块改为递进结构：

- 先建立专业判断
- 再给出能力证据
- 再展示成长路径
- 最后导向代表性项目

### 目标 3：提高版式张力

在保持整体克制的前提下，通过不对称构图、区块层级变化和项目舞台化表达，提高页面设计冲击力，而不是依赖过多特效。

### 目标 4：继续复用现有内容资产

新框架应优先复用当前已整理好的 `About`、`Experience`、`Portfolio` 内容资产，不从头改写内容体系，而是在表达层重组。

## 设计读取

Reading this as: 面向招聘方与协作方的个人作品集首页，内容核心是复杂业务场景下的产品设计与数字化实践，视觉语言应偏高级编辑感与系统叙事，而非炫技式作品展示。

建议页面参数如下：

- `DESIGN_VARIANCE: 7`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 4`

含义如下：

- 有明显版式变化，但不追求极端实验性
- 动效以进入、悬停、轻量滚动反馈为主，不做过重滚动叙事
- 页面保留呼吸感，不做高密度信息堆叠

## 方案比较

### 方案 A：编辑型首屏 + 项目剧场

特点：

- 以排版和留白建立强烈专业气质
- 首屏更像个人品牌首页
- 项目区有明显舞台化处理

优点：

- 高级感明显
- 与当前内容调性兼容

缺点：

- 容易过于安静
- 如果项目区处理不够强，会显得只有排版变化

### 方案 B：案例先行 + 能力折叠

特点：

- 首页更像 portfolio 展示页
- 项目优先级最高
- `About` 与 `Experience` 后移

优点：

- 更直接
- 更接近典型作品集浏览习惯

缺点：

- 会削弱“复杂业务系统设计”这一核心定位
- 不够适合当前已有的成长叙事内容结构

### 方案 C：叙事首屏 + 能力证据 + 项目入口（推荐）

特点：

- 首屏直接建立专业判断
- 中段用能力证据强化可信度
- 后段以成长路径和项目入口承接

优点：

- 最适合当前内容资产
- 能兼顾克制感与视觉张力
- 有利于招聘方快速建立对个人能力结构的判断

缺点：

- 对首页文案和信息层级要求更高
- 如果项目区不重做，整体提升会不够明显

## 推荐方案

采用 `方案 C：叙事首屏 + 能力证据 + 项目入口`。

该方案的核心不是增加更多模块，而是重构首页的叙事关系：

- `Hero` 负责建立判断
- `Proof Strip` 负责给出能力证据
- `About` 负责解释你的工作方式
- `Experience` 负责建立成长逻辑
- `Portfolio` 负责导向代表性案例

## 页面结构设计

### 1. Hero

`Hero` 不再以名字作为唯一视觉中心，而改为“价值主张优先”的首页首屏。

建议结构：

- 左侧：主标题、副文案、CTA
- 右侧：结构化主视觉

主标题承担的职责：

- 说明你处理的问题类型
- 建立你在复杂业务场景中的定位

副文案职责：

- 用一句话说明你连接设计、业务与落地的方式

CTA 保持两个动作：

- `查看案例`
- `联系我`

名字的呈现策略：

- 名字可以保留，但不再作为首屏最大视觉重心
- 更适合在导航、标题下方或局部标识中出现

### 2. Hero 右侧主视觉

本阶段不使用人物照片，也不使用普通装饰图。

主视觉建议采用“结构化面板”表达，体现：

- 方法论标签
- 能力维度
- 系统化感受

它的角色不是解释业务，而是建立一种“你在处理复杂系统”的视觉感受。

形式建议：

- 半抽象信息面板
- 标签块、结构块、轻量数据感元素组合
- 控制在深色体系内，减少当前偏 AI 风格的泛紫发光感

### 3. Proof Strip

这是本次新增的关键区块，用于承接 `Hero` 的抽象判断。

建议放在 `Hero` 下方，形式为 3 个能力证据块，对应以下内容：

- `复杂业务梳理`
- `多角色协同推进`
- `设计与落地平衡`

每个块不做长文案，而用：

- 一句短标题
- 一句说明
- 一组辅助标签或结构信号

该区块的作用是快速建立可信度，让页面不只停留在价值主张层。

### 4. About

`About` 需要从当前的长说明区块，压缩成“高密度专业画像”。

建议结构：

- 左侧：一句总述
- 右侧：3 组短内容

三组内容建议分别回答：

- 你是谁
- 你擅长解决什么问题
- 你如何工作

这样可以避免 `About` 与 `Hero`、`Experience` 内容重复。

### 5. Experience

`Experience` 保留成长路径叙事，不回到公司履历模式。

视觉上不再采用普通列表行，而改为 3 个阶段模块：

- `设计基础`
- `复杂产品`
- `产品与落地`

每个阶段模块包含：

- 阶段标签
- 阶段标题
- 一句说明

这一层的职责不是展开经历细节，而是让访问者快速理解能力演化路径。

### 6. Portfolio

`Portfolio` 是本次重构中最需要增强视觉冲击力的部分。

当前问题：

- 过于接近普通列表
- 项目之间层级差不够
- 还像方向型入口，不像作品舞台

建议改为“1 个主项目 + 2 个辅助项目”的舞台结构：

- 主项目：`正畸筛查与状态管理`
- 辅助项目 1：`会员自动化`
- 辅助项目 2：`PACS 读片与 AI 辅助判断`

原因如下：

- `正畸筛查与状态管理` 更适合作为综合能力主入口
- `会员自动化` 更能体现规则治理与流程优化
- `PACS 读片与 AI 辅助判断` 更能体现专业场景与人机协作能力

每个项目卡建议包含：

- 项目标题
- 一句问题描述
- 一组能力标签

避免继续使用：

- `方向 01`
- `方向 02`
- `方向 03`

这类标签较弱，不利于建立项目记忆点。

### 7. Contact

`Contact` 保持收束作用，但需更明确主次。

建议：

- 保留一个主动作：`发送邮件`
- `回到顶部` 降为弱交互
- 标题缩短，避免长段邀请式表达

这样可减少页尾的表达疲劳，让页面收束更利落。

## 页面顺序建议

推荐首页结构顺序如下：

1. `Hero`
2. `Proof Strip`
3. `About`
4. `Experience`
5. `Portfolio`
6. `Contact`

这个顺序的逻辑是：

- 第一屏建立专业判断
- 第二屏给出证据
- 第三、四屏解释“你是谁、你如何成长”
- 第五屏导向案例
- 第六屏形成联系动作

## 视觉语言建议

### 颜色

建议继续使用深色基底，但调整当前偏紫蓝的 AI 风格倾向。

方向建议：

- 主色改为更克制的冷蓝或电光蓝单色系
- 弱化双紫渐变与大面积发光
- 强调层级、边界和结构，而不是氛围光效

### 排版

冲击力主要来自：

- 大标题比例
- 左右信息张力
- 区块之间的节奏变化
- 项目区的主次关系

而不是更多装饰性视觉元素。

### 形态

建议统一圆角系统，避免页面中出现多套圆角逻辑。

当前方向建议：

- 整体偏中大圆角
- 按钮与标签统一一套规则
- 项目卡和结构块保持相同形态体系

## 动效建议

动效保持轻量，不作为主要冲击来源。

建议保留：

- 首屏渐进进入
- 模块轻量浮动或视差
- 项目卡悬停反馈

建议避免：

- 过重的滚动绑定叙事
- 大范围发光动画
- 过多持续循环效果

## 内容调整建议

### 需要弱化的内容

- `Portfolio / Design / Systems` 这类泛化眉标题
- `方向 01 / 方向 02 / 方向 03` 这类抽象编号
- 每个区块都统一采用 `kicker + title + intro` 的模板感表达

### 需要增强的内容

- `Hero` 的价值主张表达
- `Proof Strip` 的能力证据表达
- `Portfolio` 的项目问题类型与能力标签

## 边界

### 本次设计会覆盖的内容

- 首页模块顺序调整
- 各区块职责重新定义
- `Hero`、`Proof Strip`、`Portfolio` 的重点重构方向
- 页面整体视觉语言与版式策略

### 本次设计不会直接决定的内容

- 每一个具体文案的最终版本
- 每个项目卡中的详细数据展示方式
- 二级案例页结构
- 中英文文案逐字定稿

## 第一阶段优先级

如果后续进入实现，建议优先改动以下区块：

1. `Hero`
2. `Proof Strip`
3. `Portfolio`

原因：

- 这三块直接决定首页第一印象和设计冲击力
- 改完后页面的结构提升最明显
- `About` 与 `Experience` 可在第二轮继续细化

## 验收标准

完成后应满足以下条件：

- 首页第一屏能够表达“你是谁 + 你解决什么问题 + 你如何工作”
- 页面结构形成明显递进，不再是平铺模块
- `Portfolio` 具备主次层级和作品入口感
- 整体风格保持专业克制，但比当前版本更有视觉张力
- 新结构能够承接现有 `docs/profile/` 与 `docs/project/` 的内容资产
