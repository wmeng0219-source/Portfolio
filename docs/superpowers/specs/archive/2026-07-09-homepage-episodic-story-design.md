# 首页章节式叙事重构设计

## 概述

本次设计聚焦于首页表达方式升级，目标不是继续堆叠模块，也不是把现有作品集做成实验性艺术站，而是把首页从“模块化单页”调整为更有章节感、更像人物登场与篇章推进的叙事型首页。

本次确认采用的方向为：

- `方案 A：人物登场 + 专业章节推进`

设计参考来自两个方向：

- `trionn.com`：提供高级、克制、工作室式的版式和动效气质
- `ten.375.studio/en`：提供章节推进、人物登场、漫画剧集式的阅读节奏

本次设计不会照搬任一参考站的视觉形式，而是提炼两者共同有效的结构语言：

- 首页像一段连续阅读，而不是一组功能模块
- 第一幕先建立人物识别，而不是立刻解释所有能力
- 后续内容按章节推进，而不是均匀并列展开
- Typography 既承担信息，也承担一部分画面感

## 当前问题

当前首页已经完成了内容结构重组，整体逻辑比早期版本清楚很多，但表达方式仍然偏“优秀的模块化作品集”，还没有形成更强的浏览体验。

当前主要问题如下：

- `Hero` 目前仍以“价值主张 + 右侧信息面板”为主，个人识别不够强
- 名字与角色信息存在，但层级偏低，更像附属身份信息，而不是首页第一幕
- 右侧 `panel` 的存在感仍然偏强，会和左侧核心信息争夺注意力
- 页面整体虽然已有顺序，但还不够像“章节推进”，更像排版较好的 section 串联
- `Portfolio` 已经有主次结构，但还不够像“主线篇章”，戏剧性和记忆点偏弱

因此，当前问题不是内容结构错了，而是：

- 首页缺少真正的“人物登场”
- 信息层级仍偏向解释型，而不是叙事型
- section 之间的节奏差异不够大
- 页面还没有形成足够鲜明的“剧集 / 分镜”阅读感

## 设计目标

### 目标 1：把首页第一幕改成人物登场

首页打开时，用户应该先感知到：

- 这是 `Meng Wen`
- 这是一个有明确职业定位的人
- 这是一个值得继续往下看的个人/专业角色

而不是先感知一整段价值主张说明。

### 目标 2：把作品集结构改成章节推进

首页内容仍然保留作品集逻辑，但表达方式改成更像篇章：

- 第一幕：人物登场
- 第二幕：能力信号
- 第三幕：工作方式
- 第四幕：成长路径
- 第五幕：代表项目
- 第六幕：片尾行动

这样用户获得的是连续叙事，而不是“模块列表”。

### 目标 3：建立“漫画剧集感”但不牺牲专业度

本次想借用的是漫画/剧集的节奏，而不是夸张视觉风格。必须避免：

- 过重的实验动画
- 过多的装饰标签
- 为了戏剧感而损害招聘方和协作方的信任判断

最终应做到：

- 有故事感
- 有人物感
- 有章节感
- 但仍然清楚、可信、专业

### 目标 4：Typography 成为主要视觉工具

本次视觉变化的主力不应是图片或复杂插画，而应来自：

- 名字与角色层级
- 章节标题系统
- 数字、标签、旁白式短句
- 适量的 GSAP 字体动效

文字不只是内容，也是一部分画面。

## 设计读取

Reading this as: 一个面向招聘方与潜在协作方的个人作品集首页，需要从“模块式专业作品集”升级为“人物登场 + 专业章节推进”的叙事型首页，视觉语言偏克制、高级、Typography-first，介于独立工作室主页与章节式 web narrative 之间。

建议页面参数如下：

- `DESIGN_VARIANCE: 7`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 3`

含义如下：

- 版式与 section 节奏会有更明显变化，但不做极端实验
- 动效以标题、进入、章节推进为主，不做沉重 scroll hijack
- 页面需要更多留白，让人物登场和章节标题真正呼吸

## 方案比较

### 方案 A：人物登场 + 专业章节推进（推荐）

特点：

- `Hero` 先建立“人物识别”
- 后续区块像篇章推进
- 页面保留作品集逻辑，但浏览体验更像叙事型首页

优点：

- 最适合当前你的内容结构
- 可以显著提升首页记忆点
- 不会因为过于实验而削弱职业可信度

缺点：

- 需要重构 `Hero` 的视觉中心
- 需要重新设计 section 标题与过场语言

### 方案 B：强漫画分镜型

特点：

- 更强调章节编号、戏剧化标题、过场感
- 首页更像一部互动 web comic

优点：

- 风格非常鲜明
- 更容易产生强记忆点

缺点：

- 容易压过专业内容
- 对作品集场景而言风险偏高

### 方案 C：轻章节型

特点：

- 保留当前版式框架
- 只加强 section 节奏、标题和少量动效

优点：

- 风险最低
- 改动成本可控

缺点：

- 不足以真正形成“人物登场 + 剧集感”
- 容易只剩风格痕迹，没有体验升级

## 推荐方案

采用 `方案 A：人物登场 + 专业章节推进`。

核心逻辑如下：

- 首页不再一开始就解释“我能解决什么问题”
- 而是先让用户认识“这个人是谁”
- 再通过章节式推进，让能力、方法、成长与项目依次展开

换句话说：

- 不是“先卖能力，再补人物”
- 而是“先让人物出现，再让专业判断成立”

这更接近你希望的“漫画剧集感”，也更适合你现在这个带有角色转变、方法论沉淀和主线项目逻辑的作品集。

## 页面结构设计

### 1. 第一幕：Hero 作为人物登场

`Hero` 需要从“价值主张优先”改为“人物登场优先”。

新的 `Hero` 不应再把右侧面板与价值主张当成最强视觉中心，而应先把以下信息建立出来：

- `Meng Wen`
- `产品设计师 / 数字化实践者`
- 一句更克制的旁白式价值说明

建议层级：

- 第一层：名字
- 第二层：角色身份
- 第三层：一句专业定位或工作态度
- 第四层：行动按钮

这里的关键不是把信息变多，而是让人物识别变强。

### 2. Hero 的版式调整

当前左右结构可以保留思路，但不应继续让右侧 `panel` 成为强信息区。

建议改法：

- 左侧承担主要叙事
- 右侧退化为“章节氛围”或“登场辅助视觉”

右侧不再像说明卡片，而更像：

- 章节编号
- 轻量标签或场景化信号
- 字体、数字或结构元素组成的气氛层

它的职责是让 `Hero` 更像开场页，而不是再解释一遍你会做什么。

### 3. 第二幕：ProofStrip 作为能力信号页

`ProofStrip` 仍保留，但角色要从“普通证据条”升级成“第二幕的能力信号”。

建议表达：

- 更像人物登场后的“能力标签页”
- 不是纯解释，而是快速建立印象

可继续保留三条能力线：

- `复杂业务梳理`
- `多角色协同推进`
- `设计与落地平衡`

但标题和版式要更像“第二幕开场”，而不是三张普通小卡片。

### 4. 第三幕：About 作为人物设定

`About` 不再只是方法说明，而更像人物设定页。

它要回答的是：

- 这个人是什么类型的设计师
- 她擅长进入什么样的问题
- 她如何与团队工作

因此 `About` 应该保留当前内容方向，但在章节语气上更像“人物设定”，而不是简历摘要。

### 5. 第四幕：Experience 作为成长篇章

`Experience` 非常适合做成章节化表达，因为你本身就有比较清晰的角色成长路径。

建议继续保留三阶段结构：

- 设计基础
- 复杂产品
- 产品与落地

但版式上要更像“成长篇章”，而不是普通阶段列表。

核心目标是让用户感受到：

- 这是一个有升级路径的人
- 不是只会做局部页面或视觉执行

### 6. 第五幕：Portfolio 作为主线篇章

`Portfolio` 应该成为首页的“主线剧情”。

现在的主次结构方向是对的，但还需要进一步强化“主篇章感”。

建议：

- 主项目更像本季主线
- 两个辅助项目更像支线或侧章

因此这里不是普通项目列表，而是：

- 一个最值得读的“主故事”
- 两个帮助建立能力维度的“侧故事”

页面浏览到这里时，用户应该有一种“终于进入代表作主篇章”的感觉。

### 7. 第六幕：Contact 作为片尾收束

`Contact` 需要像片尾，而不是普通 CTA 区。

它的角色是：

- 在叙事结束后收束情绪
- 给出下一步动作

因此应保持简洁，不建议再堆额外说明。重点是让主 CTA 更像“片尾后的明确邀请”。

## 章节系统设计

### 章节原则

章节感不是靠大量编号来制造，而是靠以下四个东西共同建立：

- section 节奏变化
- 标题系统
- 留白和停顿
- 少量过场语言

应避免：

- 每一段都强行编号
- 每个 section 都像在扮演“艺术实验”
- 过度装饰的漫画元素

### 标题策略

首页标题应分成三层：

- 人物层标题：用于 `Hero`
- 章节层标题：用于 section 主标题
- 旁白层短句：用于 section 之间的语气连接

其中：

- `Hero` 更像登场封面
- `Portfolio` 更像主线章节
- `About / Experience` 更像设定与发展章节

### 章节语言

语气上可以适量借用“篇章感”，但必须控制分寸。

适合的方向：

- 更像章节标题
- 更像叙事旁白
- 更像人物介绍或篇章命名

不适合的方向：

- 过度文艺化
- 过度戏仿漫画标题
- 让文案失去专业判断感

## Typography 与动效设计

### Typography 角色

本次最重要的视觉升级之一，是让文字本身承担更多画面感。

重点包括：

- `Meng Wen` 作为主视觉
- 角色身份作为第二层标题
- section 标题更像章节牌
- 关键短句或数字成为过场元素

### GSAP 动效原则

字体动效应是“适量”，不能喧宾夺主。

建议动效包括：

- 名字与角色的错层 reveal
- 大标题逐层进入
- 章节标题轻量淡入与位移
- 少量编号或标签的延迟进入

可以做的：

- `y`
- `autoAlpha`
- 少量 `x`
- 极轻微 `scale`

不建议做的：

- 夸张逐字乱飞
- 高频闪动
- 过重的文本 scramble
- 影响阅读效率的字符级戏法

### Hero 字体动效建议

`Hero` 里最适合的不是复杂时间轴，而是层次明确的登场：

- 名字先出现
- 角色身份随后出现
- 旁白式价值说明再进入
- CTA 最后进入

如果需要更强一点的细节，可以只在名字或角色上加极轻的字重/间距变化感，而不是做复杂特效。

## 交互结构设计

### 整体交互方向

整页交互结构可以借鉴 `ten.375.studio` 的“像翻阅一部连续作品”的感觉，但不适合完全照搬。

适合借鉴的是：

- 分幕式浏览体验
- section 之间的停顿感
- 每一幕都像新的画面出现
- Typography 参与交互

不适合借鉴的是：

- 过重实验交互
- 牺牲信息效率换戏剧感
- 让用户必须“玩懂”页面才能获得信息

### 首页交互结构的边界

本次不建议把首页做成：

- 完整长卷轴 web comic
- 复杂 pin 住多屏的 scroll story
- 依赖强滚动控制的实验站

更合适的是：

- 首页仍然是作品集首页
- 但阅读体验更像在看章节
- section 进入更像新一幕被揭开

## 动效与响应式约束

### 桌面端

桌面端可以保留：

- 人物登场的分层进入
- 章节标题的 reveal
- 轻量 section 过场
- `Hero` 的 Typography-first 视觉

### 移动端

移动端必须更克制：

- 保留人物登场层级
- 保留章节切换节奏
- 降低标题动效复杂度
- 避免依赖大面积横向构图

### Reduced Motion

必须支持 `prefers-reduced-motion`：

- 所有文字动效可降为快速淡入
- 取消持续型漂浮
- 取消不必要的滚动位移

## 技术设计

### 实现范围

本次设计会主要影响以下区域：

- `Hero`
- `ProofStrip`
- `Portfolio`
- section 标题系统
- 页面级 motion 组织

影响较小的区域：

- `About`
- `Experience`
- `Contact`

这些区域更多是语气和节奏统一，不一定需要大改结构。

### 推荐实现方式

建议保留现有首页信息结构和路由组织，只在表达层做重构：

- 重排 `Hero` 的 DOM 层级与视觉中心
- 减弱或改造现有 `panel`
- 为 section 引入更统一的“章节标题 + reveal”规则
- 用 GSAP 做轻量层级动效

### 不做的内容

本次不包括：

- 完整重写为实验性滚动叙事网站
- 改写全部 locale contract
- 增加复杂的漫画插画或视觉资产系统
- 引入沉重的 ScrollTrigger pin 剧场

## 成功标准

如果本次设计实现到位，最终首页应满足：

- 第一眼更像“人物登场”，而不是普通作品集 Hero
- 用户能更快记住 `Meng Wen` 和你的角色定位
- section 浏览更像章节推进，而不是模块堆叠
- `Portfolio` 更像主线篇章，而不是普通项目分组
- Typography 成为视觉重点之一
- 整体有“漫画剧集感”的节奏，但仍然专业、可信、清晰
