# 首页 GSAP 动效设计

## 概述

本次设计聚焦于首页动效层升级，目标不是新增炫技效果，而是在现有首页结构已经稳定的前提下，为页面加入更有层次的进入动画、滚动唤醒和微交互反馈。

本次确认采用的方向为：

- `方案 A：分层叙事动效`

动效基调参考 `trionn.com` 的高级工作室表达，但不直接复制其视觉形式，而是提炼其核心气质：

- 克制
- 有节奏
- 有层次推进
- 通过轻微位移、透明度和少量缩放建立质感

本次范围限定为：

- 首屏自动入场
- 其余首页区块滚入触发
- 按钮、卡片、项目区块、导航加入 hover 或轻反馈
- 保持现有首页结构与文案职责不变

## 当前情况

当前项目已经具备一套基础 GSAP 使用方式，主要集中在 `Hero`：

- 首屏文案已存在简单的分层进入
- 右侧面板已有轻量滚动位移
- 其他区块尚未建立统一的进入动效语言
- Hover 反馈主要依赖 CSS，本身较轻，缺少统一的节奏和触感

因此现在的问题不是“有没有动画”，而是：

- 动画语言不够统一
- 动画重心集中在 `Hero`，后续区块显得偏静
- 页面整体缺少从首屏到案例区的连续节奏
- 微交互存在，但不够构成完整的高级感

## 设计目标

### 目标 1：建立统一的首页动效语言

首页所有主要区块应共享同一套动效原则：

- 轻位移
- 淡入
- 分层错开
- 不做夸张飞入

这样用户在从首屏滚动到后续内容时，会感受到连续的视觉节奏，而不是零散的局部动画。

### 目标 2：强化首页叙事推进

动效不只是装饰，应服务于当前首页的内容结构：

- `Hero` 建立第一印象
- `ProofStrip` 建立能力证据
- `About`、`Experience` 展开方法与成长逻辑
- `Portfolio` 强化代表性案例入口
- `Contact` 完成收束

因此动效应该帮助用户“被引导着往下看”，而不是频繁打断阅读。

### 目标 3：补足高级感而不过度表演

参考站点的可借鉴点在于节奏和张力，而不是大量实验性交互。本次动效应做到：

- 第一眼有质感
- 滚动过程中有被唤醒的感觉
- Hover 有明确反馈
- 但不压过内容本身

### 目标 4：兼顾可维护性与可访问性

本次动效不应变成分散在每个组件里的无序补丁，而应该形成可复用规则。并且必须：

- 支持 `prefers-reduced-motion`
- 移动端减弱视差和过多 stagger
- 避免过重依赖 layout 属性动画

## 设计读取

Reading this as: 一个已经完成内容与结构重构的个人作品集首页，现在需要通过 GSAP 建立更统一的高级动效语言，让页面更接近数字工作室的专业气质，但仍保持作品集场景下的克制和可读性。

建议页面参数如下：

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 6`
- `VISUAL_DENSITY: 4`

含义如下：

- 页面节奏有明显变化，但不过度实验
- 动效存在感清晰，但优先服务阅读和结构
- 视觉保持留白，不通过大量动画元素制造“热闹感”

## 方案比较

### 方案 A：分层叙事动效（推荐）

特点：

- 首屏自动入场
- 后续区块滚入唤醒
- 加入系统化 hover 反馈

优点：

- 首页从上到下都形成统一节奏
- 最适合当前已完成的首页结构
- 接近参考站的高级工作室感

缺点：

- 需要梳理每个区块的触发策略
- 需要统一动效参数，否则容易零散

### 方案 B：极简高级版

特点：

- 重点只在 `Hero` 和 section 淡入
- 微交互最少

优点：

- 风险最低
- 最不容易显得“做太多”

缺点：

- 整体存在感偏弱
- 与参考站相比，层次感不够完整

### 方案 C：表现力更强版

特点：

- 更明显的位移、缩放和错位
- `Portfolio`、卡片、导航都有更强反馈

优点：

- 第一眼冲击更强
- 更容易让用户感知“设计过”

缺点：

- 容易压过当前内容本身
- 对个人作品集而言更容易用力过猛

## 推荐方案

采用 `方案 A：分层叙事动效`。

核心原则是：

- 首屏自动进入，快速建立第一印象
- 区块在滚动中被轻量唤醒，形成往下阅读的节奏
- 微交互提供触感，但不成为主角
- 不依赖复杂的时间轴大秀，而用统一规则建立品质感

## 动效语言

### 基础原则

全站动效以以下属性为主：

- `y`
- `autoAlpha`
- 少量 `scale`
- 极轻量 `x`

避免使用：

- 大角度旋转
- 弹跳式 easing
- 大范围缩放
- 依赖 `top`、`left`、`width`、`height` 的 layout-heavy 动画

### 推荐 ease

- 主进入：`power3.out`
- Hover：`power2.out`
- 视差：`none`

### 推荐时长

- 首屏分层进入：`0.7s - 0.95s`
- 区块滚入：`0.65s - 0.85s`
- Hover：`0.2s - 0.35s`

### 推荐 stagger

- 文案序列：`0.08 - 0.12`
- 卡片序列：`0.1 - 0.16`

## 页面级动效设计

### 1. Hero

`Hero` 是本次动效的重心，应保持当前已有结构，只增强其层次和完成度。

建议动效：

- `kicker -> title -> body -> actions -> meta` 按序上移淡入
- 右侧 `panel` 稍晚半拍进入
- 背景 `glow` 做极轻微呼吸变化
- 右侧面板保留很弱的 scroll-linked 漂浮感

要求：

- 首屏入场在初次加载时自动触发
- 不做大幅横向飞入
- 不让 `panel` 与 `ProofStrip` 的“能力证据”发生表达重叠

### 2. ProofStrip

`ProofStrip` 是从抽象判断过渡到能力证据的第一段，因此动画应更像“被点亮”。

建议动效：

- 整个 section 先轻微上移淡入
- 三张卡片 stagger 出现
- 标签、标题、正文不再分别强行拆动画，避免过碎

Hover：

- 卡片轻微上浮
- 阴影和边框对比略增强
- 不做明显缩放

### 3. About

`About` 应呈现为专业画像区块，动画比 `ProofStrip` 更稳。

建议动效：

- 标题区先出现
- 三张画像卡片再统一 stagger

Hover：

- 卡片轻微上浮
- 标签或标题可有轻量亮度变化

### 4. Experience

`Experience` 是成长阶段区，应强调“阶段推进”的感觉。

建议动效：

- 区块标题先进入
- 三个阶段块从下到上依次唤醒
- 位移量略小于 `ProofStrip`，避免抢戏

Hover：

- 阶段块提升层次感即可
- 不做强烈动态位移

### 5. Portfolio

`Portfolio` 是首页后半段最值得强调的区块，动效层次应高于 `About` 和 `Experience`，但仍低于首屏。

建议动效：

- 标题区先进入
- 主项目卡片后进场，形成“舞台亮起”的感觉
- 两个辅助项目再做短 stagger

Hover：

- 主项目可做轻微上浮与阴影增强
- 辅项目 hover 与主项目一致，但强度略低
- 链接箭头或按钮可做极短距离位移

### 6. Contact

`Contact` 作为收束区块，动画应简洁。

建议动效：

- 区块整体淡入
- CTA 按钮略晚一点进入

Hover：

- 主 CTA 具备更明确的上浮和阴影变化
- 次要链接只保留轻微透明度或位移反馈

### 7. Navbar

导航不应过度表演，只提供高级感和清晰反馈。

建议动效：

- 初次渲染时轻淡入
- 桌面端链接 hover 更利落
- 移动端菜单开合保持清楚，不做复杂动画堆叠

要求：

- 不破坏现有可访问性修复
- 不牺牲焦点管理和菜单状态清晰度

## 触发规则

### 首屏

- `Hero` 在页面初次加载后自动触发
- 首屏动效不依赖用户滚动

### 其他区块

- `ProofStrip`、`About`、`Experience`、`Portfolio`、`Contact` 采用滚入触发
- 触发时机应偏“稍早”，让用户看到区块时动画基本完成一半以上

推荐触发区间：

- `start: "top 82%"`
- `once: true`

### Hover

- 所有 hover 即时响应
- 持续时间短于进入动画
- 桌面端明显，移动端自动降级

## 响应式与可访问性

### 桌面端

- 保留完整分层进入
- 保留 `Hero` 面板的轻量漂浮
- 保留卡片 hover

### 移动端

- 保留首屏基础入场
- 保留区块 reveal
- 降低 stagger 数量或缩短 stagger 时差
- 去掉明显视差与过强 hover 预期

### Reduced Motion

使用 `gsap.matchMedia()` 统一处理：

- 当 `prefers-reduced-motion: reduce` 时
- 进入动画改为极短淡入，或直接设为终态
- 取消持续型漂浮与 scroll-linked 位移

## 技术设计

### 动画组织方式

建议建立两层组织：

- 组件内：保留与结构强绑定的动画，如 `Hero`
- 页面通用：抽象 section reveal 和 hover 规则，避免每个组件重复手写参数

建议抽出的能力：

- `section reveal`
- `card stagger reveal`
- `button / card hover`

### GSAP 规则

- 优先使用 `fromTo()` 明确起止状态
- 使用 `autoAlpha` 代替单纯 `opacity`
- 使用 `y`、`scale` 等 transform aliases
- 使用 `gsap.matchMedia()` 处理断点和 reduced motion
- 对 hover 动效保留 tween 控制，避免叠加冲突

### 不做的内容

本次不包含：

- 大型 scroll storytelling
- 横向滚动叙事
- 视频或 3D 场景动画
- 自定义时间轴编排整页长序列
- 大量依赖 ScrollTrigger pin 的交互设计

## 测试与验收

### 功能验收

需要确认：

- 首屏加载有分层进入
- 各 section 在滚入时出现
- Hover 在按钮、卡片、项目入口上有一致反馈
- 移动端没有出现过度动画
- reduced motion 下动画被正确降级

### 工程验收

需要通过：

- `npm test`
- `npm run build`

并新增或更新适度的测试，至少覆盖：

- 关键动画 hook 或属性标记存在
- `prefers-reduced-motion` 分支不会报错
- 关键组件改动不破坏现有交互测试

## 实施边界

本次设计是“首页动效层增强”，不是再次改写首页信息架构。因此：

- 不调整首页区块顺序
- 不重写文案 contract
- 不改变 `Hero / ProofStrip / About / Experience / Portfolio / Contact` 的职责边界
- 不引入与当前项目气质不符的炫技动效

## 成功标准

如果本次设计实现到位，最终结果应满足：

- 首页第一眼更有完成度和设计气质
- 滚动浏览时有连续节奏
- 微交互提升触感，而不打扰阅读
- 动画语言统一，而不是局部点缀
- 用户能感受到参考站的高级感来源于“节奏与克制”，而不是特效堆砌
