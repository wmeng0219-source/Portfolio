# 参考 `gsap.com` 的 Hero 与 Portfolio 大改版设计

## 概述

本次设计覆盖首页中的两个核心区块：

- `Hero`
- `Portfolio`

这不是上一版“中等强化”的延续优化，而是一轮明确的骨架级重做。

用户已经确认本次边界如下：

- 允许重做 `Hero + Portfolio` 的 DOM 骨架
- 允许显著参考 `gsap.com` 的配色与舞台感
- 允许明显压缩首页文案密度
- 允许让首屏和案例区产生“一眼能看出变了”的观感

本次目标不是复制 `gsap.com` 的内容类型，而是借用它的品牌首页表达方式，把当前作品集首页改造成更强的品牌舞台入口。

## 设计方向

本次采用方向 `B / GSAP Brand Stage`。

它的核心定义是：

- `Hero` 做成超大标题主导的品牌舞台
- `Portfolio` 做成精选案例入口，而不是普通三卡列表
- 页面允许明显换肤
- 信息量明显减少
- 节奏、配色、装置和 CTA 都向品牌首页靠拢

这比此前的“品牌感增强”更激进，但又不像纯 showcase 那样完全压过作品集本身。

## 设计目标

### 目标 1：首屏必须产生“品牌首页”而不是“作品集模块”的第一印象

当前首屏虽然已经使用了暗色、大标题和少量装饰，但第一眼仍然像一个排版良好的作品集 Hero。

本次需要把它改成真正的品牌舞台：

- 超大标题占据首屏绝对支配地位
- 信息量压缩到一句主张 + 一个 CTA
- 背景装置成为大尺度舞台层，而不是局部小组件
- 配色从当前紫黑气质切换到更接近 `gsap.com` 的高对比深色底与亮色信号

### 目标 2：Portfolio 必须从“信息卡片区”升级为“精选案例入口”

当前 `Portfolio` 即使已经做成三卡，也仍然像三个并列的信息模块。

本次要改成更强的品牌陈列：

- section 本身就是一个 statement
- 案例卡片不是“解释项目”，而是“引导进入项目”
- 卡片可以保留三项数据映射，但在视觉上要更像精选 showcase
- 三张卡片之间要建立更明显的主次与浏览顺序

### 目标 3：配色要明显换挡，形成新视觉记忆点

当前站点以紫黑为主，虽然干净，但和 `gsap.com` 级别的品牌站相比，识别度不够强。

本次允许参考 `gsap.com` 的配色逻辑：

- 深色背景保持高对比
- 引入高饱和亮色作为信号色
- 大面积文字与 CTA 使用更鲜明的明暗关系
- 局部荧光感只作为品牌信号，而不是全局泛滥

### 目标 4：动效要更“舞台化”，而不是局部微交互优化

之前的问题不是页面不精致，而是节奏变化不足以重建体验。

本次要把动效层级改成真正有“开场感”的结构：

- 首屏先建立舞台，再进入标题，再落 CTA
- 背景装置具备更强的大尺度运动气质
- Portfolio 进入方式更像被揭开或推入，而不是简单 reveal
- hover 依旧要精确，但整体动效基调必须明显升级

## 当前问题

### 当前 Hero 的问题

当前 Hero 的主要问题不是视觉质量差，而是“仍然太像一个作品集 Hero”：

- 大标题虽大，但仍服务于常规内容阅读
- 辅助文案密度依然偏高
- 视觉装置存在，但没有成为舞台背景
- 配色仍延续原站的安全区，没有形成更强烈的新记忆点

因此用户会感觉“改了，但没什么变化”。

### 当前 Portfolio 的问题

当前 Portfolio 的主要问题是骨架仍是卡片集合：

- section 标题只是标题，不是 statement
- 三卡结构太平均，入口感不强
- 文本依然偏说明型，而不是展示型
- hover 和 reveal 都属于改良版，但不构成风格切换

这使它看起来更像“优化后的作品集列表”，而不是“品牌化精选案例入口”。

## 参考对象提炼

### 本次真正借鉴的是 `gsap.com` 的四种能力

- 用超大标题在 1 秒内建立气质
- 用高对比深色底 + 亮色信号形成识别
- 用大尺度背景装置提供舞台感
- 用极少文案和极明确 CTA 把注意力聚焦

### 明确不借鉴的内容

- 不照搬 `gsap.com` 的品牌文案
- 不照搬其导航结构和产品分发逻辑
- 不把首页做成插件展示门户
- 不复制其具体 SVG 或图形资产

## 核心设计决定

### 决定 1：Hero 改成“超大标题 + 一句主张 + 一个 CTA”的高压首屏

当前 Hero 中保留过多次级信息，不利于形成品牌舞台。

本次改法：

- 顶部信息条可以保留，但必须极弱
- 主标题改成首屏绝对核心
- 辅助文案压成一句极短主张
- 只保留一个 CTA
- ticker 不再作为底部信息带存在

换句话说，`Hero` 将从“说明型首屏”切成“品牌开场型首屏”。

### 决定 2：Hero 的装置层要从“小装饰”升级为“大舞台”

当前几何图形仍然是局部视觉件。

本次必须重做成更接近品牌站的舞台背景：

- 装置面积明显放大
- 允许使用更强的发光与透视感
- 背景运动以大尺度、慢速、连续为主
- 装置与标题形成前后景关系，而不是左右平权关系

### 决定 3：Hero 文案压缩为“主张型表达”

用户已经允许大幅压缩首页文案。

因此本次不追求 Hero 里的完整自我介绍，而采用更品牌化的表达方式：

- 主标题负责建立印象
- 一句短文案负责解释方向
- 更详细的能力说明下沉到后续 section

这意味着 Hero 不再承担完整介绍职责，而只承担“打开体验”的职责。

### 决定 4：配色切换到 `gsap.com` 式深底 + 亮色信号系统

当前紫色方案不再是本次约束。

新的色彩策略：

- 背景以深黑 / 深蓝黑为主
- 主文字保持极高亮度
- 亮色参考 `gsap.com` 的荧光绿 / 酸性绿逻辑
- 可在少数局部引入偏蓝绿或黄绿作为层次变化

配色重点不是“变绿”，而是让页面具备更强的品牌识别和速度感。

### 决定 5：Portfolio 从“三张并列卡”升级为“精选案例舞台”

Portfolio 不再只是把三个案例平铺出来。

新的结构应更接近：

- 一个更强的 section statement
- 一个更有主次的 showcase 布局
- 三张案例作为精选入口，而不是三份信息说明

允许出现以下变化：

- 三张卡片尺寸不完全等权
- 首张卡成为默认主入口
- 其余两张卡成为从属入口
- 布局可从简单三等分改为 1 强 2 弱，或强节奏三段式

### 决定 6：Portfolio 文案从“说明项目”改成“引导进入”

既然首页允许压缩文案，Portfolio 卡片就不该继续写长描述。

新的文案策略：

- 卡片保留项目标题
- 卡片只保留一条短句或短标签
- metric 继续保留，但表达更品牌化
- 详情信息留给项目详情页承接

### 决定 7：动效从“优化”切换为“开场式舞台节奏”

这次动效不能再只是收数字。

新的动效原则：

- Hero 首屏有明确的开场感
- 标题出现方式更有压迫感
- 装置层具有更明显的品牌站运动气质
- Portfolio 的进入要像被推出舞台
- CTA 和卡片 hover 继续保持精确，但整体基调更有侵略性

## 组件级设计

### Hero 组件

涉及文件：

- `src/components/Hero/index.jsx`
- `src/components/Hero/Hero.module.css`
- `src/locales/zh.json`
- `src/locales/en.json`

新的 Hero 需要满足以下要求：

- DOM 骨架允许重写
- 删除当前 ticker 结构或将其彻底降级为非主视元素
- 删除当前说明型正文结构，改成一句主张式副标题
- 主 CTA 继续跳转到 `#portfolio`
- 背景装置面积和权重显著提升
- 标题与装置形成明确前后景
- 文案层级明显减少

建议结构方向：

- 极简 header line
- 超大标题 block
- 一句主张
- 单一 CTA
- 大尺度背景舞台装置

### Portfolio 组件

涉及文件：

- `src/components/Portfolio/index.jsx`
- `src/styles/global.css`
- `src/locales/zh.json`
- `src/locales/en.json`

新的 Portfolio 需要满足以下要求：

- DOM 骨架允许重写
- 允许从简单三等分改成更有主次的 showcase 布局
- 卡片的文案密度必须下降
- 卡片的入口感必须增强
- section 标题区必须更像品牌 statement

允许的布局方向包括但不限于：

- `1 强 + 2 弱`
- `主卡横向扩展 + 两张辅卡堆叠`
- `三段式但有明显尺寸差`

无论采用哪一种，都必须满足：

- 三个案例都可见
- 三个案例都能进入详情页
- 第一眼能看出“主入口”和“辅助入口”

## 文案策略

### Hero 文案策略

Hero 的目标不是完整介绍个人经历，而是建立强烈品牌感。

因此文案要求：

- 标题更短
- 副标题更短
- 信息密度更低
- 口语式说明减少

示例方向不是最终文案，只是表达方式示意：

- 标题：更像主张
- 副标题：更像一句价值承诺
- CTA：保持单一行动

### Portfolio 文案策略

Portfolio 首页卡片不再使用较长句式解释项目背景。

每张卡在首页只承担三件事：

- 建立主题识别
- 给出一个强结果或强标签
- 激发进入详情页的意愿

## 配色策略

### 主色关系

- 背景：深黑 / 蓝黑
- 主文字：高亮白
- 信号色：荧光绿 / 酸性绿
- 次级辅助：低饱和冷灰或偏蓝灰

### 配色应用规则

- 亮色只用于关键部位
- 不让整页充满霓虹效果
- CTA、核心指标、装置高光、局部 hover 可使用亮色
- 正文大段文字仍保持可读性优先

## 动效设计

### Hero 动效

新的 Hero 动效要更像品牌站开场，而不是普通 reveal：

- 背景装置先建立环境
- 标题以更强的位移或遮罩节奏进入
- 副标题和 CTA 稍后跟上
- 页面初始就能感受到“舞台已经被点亮”

### Portfolio 动效

Portfolio 的进入要具备“被推出前台”的感觉：

- section statement 先出现
- 主卡优先进入
- 辅卡跟进
- hover 反馈不做夸张跳跃，但允许更明显的亮色联动

## 数据与工程边界

### 保持不变

- 继续使用 `src/data/projects.js`
- 继续使用 `src/locales/*.json`
- 继续使用当前路由结构
- 继续只使用 GSAP

### 允许调整

- 允许新增大量 locale 字段以承载新的短文案
- 允许重写 `Hero` 与 `Portfolio` 的 DOM 骨架
- 允许重写 `useHomepageMotion` 的节奏逻辑
- 允许替换当前局部装饰实现方式

## 非目标

本次明确不做以下内容：

- 不改 `About`
- 不改 `Experience`
- 不改 `Contact`
- 不改项目详情页内容结构
- 不把全站所有 section 一次性换肤
- 不引入新的动画库

## 验证标准

### 视觉标准

- 第一眼必须明显感觉首页已经换了一种风格
- `Hero` 必须更像品牌站开场，而不是作品集说明页
- `Portfolio` 必须更像 showcase 入口，而不是列表
- 配色必须形成新记忆点

### 交互标准

- `Hero` CTA 仍正常跳转到案例区
- 三个案例入口都正常可点
- 动效明显升级，但不影响可读和可用
- `prefers-reduced-motion` 下仍保持基本可读性

### 工程标准

- `npm test` 通过
- `npm run build` 通过
- 不破坏现有多语言和数据映射

## 范围判断

本规格聚焦 `Hero + Portfolio` 的品牌化大改版，范围明确，可以直接进入新的实现计划阶段。
