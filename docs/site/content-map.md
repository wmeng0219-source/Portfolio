首页的核心表达已经整合到实际页面中，因此本文不再承担“写一版待实现首页文案”的职责，而是作为维护文档，回答以下问题：

- 当前每个区块已经承接了什么角色。
- 后续如果继续调整，应该优先回到哪一层资料取材。

## 使用建议

- 页面内容维护优先引用正式整理文档，不直接从原始材料复制。
- 若页面结构已改动，先更新本文的“区块职责”和“来源映射”。
- 若新增项目案例，先更新 `docs/project/`，再同步到页面和项目详情页。
- 若要追溯某一轮设计和实现决策，前往 `docs/superpowers/` 查看过程文档。
- 当前整理顺序保持为：`先整理事实 -> 再提炼映射 -> 最后更新页面`。

## 内容准入与更新顺序

案例是否进入页面，不由文案完成度决定，而由事实与证据就绪度决定。更新前先检查 `../project/content-readiness.md`，再按以下规则取材：

| 页面位置 | 最少应承接的内容 | 不应承接的内容 |
| --- | --- | --- |
| 首页项目入口 | 项目命题、个人角色范围、一个有口径的结果、查看详情的理由 | 长背景、功能清单、没有来源的强结论 |
| 案例详情页 | 现场、根因、约束、决策、机制、落地、结果与反思 | 只展示高保真图或纯项目过程日志 |
| About / Experience | 职业演进、真实职责范围、可迁移的工作方式 | 与项目详情重复的指标与功能说明 |
| More Cases | 有清晰问题和机制、但证据尚不足以承担首页主案例的项目 | 用未验证成果补充数量 |

首页三个主案例继续分别证明：规则与治理、流程与协作、人机边界。任何新案例进入首页前，必须说明它补足了什么能力，而不是重复已有案例。

### 领域迁移表达

医疗场景是经验来源，不是作品集能力的边界。页面提炼时可使用以下真实能力映射，但必须回扣具体项目证据：

- 多角色诊疗协作 → 企业工作流、权限与交接系统。
- 正畸状态与漏斗 → CRM、生命周期管理与经营分析。
- 会员规则与结算审计 → 定价、权益、订单与财务治理。
- PACS 人机复核 → 高风险 AI 辅助决策、质控与反馈闭环。

不要把行业术语替换成空泛能力标签；每项迁移表达都应链接到一个可展开的项目判断。
