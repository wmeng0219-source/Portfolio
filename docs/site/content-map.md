# 内容映射

本文用于把 `docs/profile/` 与 `docs/project/` 中已经整理过的事实，收束成网站各页面区块可直接使用的内容方向。

当前目标不是直接产出最终网页文案，而是先明确每个区块应该承接什么信息、从哪里取材、表达边界是什么。

## Hero

- 主要来源：`docs/profile/overview.md`
- 区块目标：第一屏先建立稳定、清晰的求职身份认知，让访问者快速知道“你是谁”“你主要做什么”
- 当前主表达：`产品经理 / 设计复合型人才`
- 支撑信息：
  - 一句话简介：从复杂 B 端产品设计出发，连接业务、产品、流程与数字化建设，并持续探索 AI 在产品工作流中的应用
  - 辅助标签：医疗数字化产品经理、ITBP、业务分析与流程设计、UI / UX 背景、AI 工作流实践
- 表达边界：
  - 第一屏不强打行业细分标签，行业背景放到后续区块展开
  - 不把“设计”和“产品”并列成两个割裂身份，而是突出“产品经理是主身份，设计背景是差异化优势”
  - 文案风格保持专业、克制、清晰，不使用空泛口号

## About

- 主要来源：`docs/profile/overview.md`、`docs/profile/domain-and-strengths.md`
- 区块目标：解释你的工作方法、价值判断和能力结构，而不是重复简历信息
- 建议承接内容：
  - 你长期所处的业务场景：儿童口腔医疗数字化、连锁门诊、医生工作流、会员与经营场景
  - 你的工作方式：从一线调研出发，识别业务问题，转化为流程、系统与协作方案
  - 你的价值取向：关注高频、低价值、可标准化的问题，强调系统建设服务业务目标
  - 你的能力结构：设计能力、产品能力、业务能力、分析能力、跨团队协同能力
- 页面表达重点：
  - 强调“方案设计能力”和“从问题到落地的完整思考过程”
  - 不把 About 写成自我评价堆叠，而要让它成为后续项目案例的理解入口

## Experience

- 主要来源：`docs/profile/career-timeline.md`
- 区块目标：展示成长路径与角色演变，让访问者理解你的能力不是跳跃出现的
- 建议使用结构与表达（按阶段提炼成长路径）：
  - 区块标题：`跨设计、产品与业务现场。`
  - 区块引导语：`我的成长不是岗位名称的变化，而是逐步从设计执行走向复杂业务理解、产品方案判断与落地推进。`
  - `2019 - 2020` (设计基础)：UI 设计师，积累视觉设计、界面规范与组件化基础
  - `2020 - 2022` (复杂产品)：从页面设计走向信息架构与复杂业务理解，产品思维开始成形
  - `2022.07 - 2023.04` (开始参与产品判断)：进入复杂后台与研究平台场景，开始参与需求分析与产品判断
  - `2023.04 - 至今` (产品与落地)：在儿童口腔医疗数字化场景中承担产品经理 / ITBP 角色，在业务现场推动数字化方案真正发生

## Portfolio

- 主要来源：`docs/project/`
- 补充依据：如需追溯细节，再回看 `docs/origin/`
- 区块目标：用具体项目证明你的问题判断、方案设计和落地推进能力
- 项目筛选原则：
  - 优先选择能体现“复杂流程 + 多角色协作 + 系统承接 + 业务结果”的项目
  - 优先选择有明确结果或阶段性数据的项目
  - 每个项目页面表达尽量统一为“背景 / 问题 / 角色 / 关键方案 / 结果”

### 项目 1：会员自动化

- 来源：`docs/project/会员自动化.md`
- 页面定位：体现你在复杂业务规则梳理、流程自动化和财务治理协同上的能力
- 可提炼摘要：
  - 面向门店收银、会员升级、优惠和财务核对场景，重构会员、卡券、收费、账单之间的规则关系
  - 推动高频会员流程从人工操作转向系统自动承接，降低一线误操作和财务核对成本
  - 上线后覆盖 `20+` 家门店，门店处理时间从 `4-5` 分钟缩短到约 `1` 分钟，财务月底对账从约 `3` 天缩短至约 `1` 天

### 项目 2：正畸筛查与状态管理

- 来源：`docs/project/正畸筛查与状态管理.md`
- 页面定位：体现你对复杂业务流程重构、角色协作设计和连续管理机制设计的能力
- 可提炼摘要：
  - 将原本依赖面评会和线下协作的离散筛查流程，重构为可持续跟进的矫正前置管理机制
  - 主导角色职责重构、推荐逻辑、再筛查机制、状态化管理与系统功能拆分
  - 建立从推荐到预约的连续漏斗链路，阶段性数据中筛查率、结论率、报告率和预约率已可被系统观察

### 项目 3：PACS 读片与 AI 辅助判断

- 来源：`docs/project/PACS读片与AI辅助判断.md`
- 页面定位：体现你在专业场景下处理人机协作、结构化流程和 AI 边界设计的能力
- 可提炼摘要：
  - 围绕儿童口腔影像读片场景，先建立结构化读片与病历同步能力，再推进 AI 辅助判断方案
  - 在 V2 阶段主导产品与设计，明确 AI 提示、医生复核、免责边界与数据回收闭环
  - AI 小牙片读片上线后，平均单张龋齿发现数从 `1.43` 提升至 `3.46`

## 使用建议

- 页面内容编写优先引用正式整理文档，不直接从原始材料复制。
- 若后续补充新的项目案例，先更新 `docs/project/`，再同步到网站表达层。
- 若项目需要追溯事实依据，再回看 `docs/origin/` 中的原始材料。
- 当前网站内容整理遵循：`先整理事实 -> 再提炼能力和方法 -> 最后生成网站表达`。
- 页面文案不从模糊定位反推，而优先从 `docs/project/` 与 `docs/profile/` 的整理结果中提炼。
