- 三段标题从「复杂 B 端 / 产品 × 设计 / 交付与 AI」改成「复杂业务系统 / 业务与系统之间 / 数据与交付」——不再把设计摆成并列身份。
- 「服务 20+ 连锁门诊」移进工作经历，个人优势里不再重复。

## 工作经历

### 上海极橙医疗科技有限公司｜产品经理｜2023.04–2026.09

```
服务 20+ 连锁门诊，处在业务部门与 IT 之间，负责门诊运营、会员与结算、
正畸筛查、影像读片几条业务线的系统建设，从业务调研、规则梳理，
到 PRD、交互与界面方案，一路跟到上线。

● 业务调研与需求治理：长期下门店跟岗，把一线零散说法收敛成结构化需求，
  区分「规则问题 / 流程问题 / 系统问题」，减少方案反复。
● 规则与方案设计：梳理会员权益、收银结算、正畸筛查流转等复杂业务规则，
  独立输出流程图、PRD 与可直接开发的高保真交互方案，对齐业务与财务口径。
● 交付推进：拆解任务、跟研发排期、协调上线，负责验收与使用反馈闭环；
  核对交互还原度与异常操作路径，减少研发理解偏差。
● 跨团队协同：对接业务、IT、研发、算法与财务多方；影像 AI 项目中与算法
  团队共同定义人机分工与异常处理边界。
```

**改了什么**
- 职位名：`UI 设计师（兼产品职责）` → `产品经理`。附件和在线两份统一，删掉「兼」。
- 补了 ITBP 的实质：不是「负责需求」，而是「区分规则问题/流程问题/系统问题」——这是甲方 PM 最值钱的动作。
- 设计部分不单列成一条能力项，也不用「前期做设计、后来转产品」的时间切割，改成把它放回交付链条里：
  1. 开头一句用链条描述职责（`从业务调研、规则梳理，到 PRD、交互与界面方案，一路跟到上线`）——设计是链条中的一环，不是另一个身份；
  2. 方案条写 `可直接开发的高保真交互方案`——把设计能力挂在产品交付上；
  3. 交付条写 `核对交互还原度与异常操作路径`——设计背景在验收环节的真价值。
- 不写时间节点：用户 2026-10-28 确认 UI 设计是贯穿全程一直在做的，写成「前期/转岗」既不符合事实，也会主动制造「转型」话题。模糊掉时间段，只呈现同时承担的结果。

### 正畸咬合筛查系统｜产品负责人（业务调研 → 规则设计 → 上线）｜2025.04–2026.04

```
项目背景：矫正前需先筛出需要干预的儿童，但这项工作长期依赖医生个人判断与口头交接，
本应记录过程的评估表几乎无人填写，门店执行到哪一步也无从查证。

核心工作：将分散的筛查重构为护士采集资料、儿牙医生初筛、矫正医生下结论、运营跟进的
分段流程，各角色在同一份记录上依次接力；由系统按年龄与发育阶段筛选对象并并入患者
原有预约，避免为筛查单独增加一次到诊。

项目成果：2026 年 2 月全门店上线，累计提交筛查结论 1.85 万条；同期，判定需矫正患者
的成交比例由约 30%—40% 升至 50%—60%。
```

**说明**
- 按《招聘网站项目经历撰写规范》三段式重写，约 150 字。
- 「同期」二字是有意保留的：事实底稿写明同期成交率变化不能全部归因于本项目，不能写成「带来提升」。
- 单位用「条」不用「名」：未确认独立患者去重。
- 删掉「预约锁定 0.55 万」：三段式里成果只留最有说服力的一到两个指标，漏斗终点留给面试展开。

### 连锁门诊会员自动化与收银结算｜产品设计｜2025.07–2025.10

```
项目背景：会员卡种多、各地区规则不统一，同一操作在不同卡种上的要求并不相同，日常
只能依靠人工核算差价、手工改价与群内审批来维持。

核心工作：将各卡种、各地区的权益与折扣条件整理为一张规则表，由系统在开卡、囤卡、
升级、退卡时按卡种自动匹配对应规则，替代原先依赖记忆和手工计算的做法。

项目成果：20+ 门店落地，典型会员卡升级操作由 3—4 分钟缩短至约 1 分钟，折扣与退费
的每一步均可追溯。
```

**说明**
- 按规范三段式重写，约 130 字。
- 背景只写「规则不一致导致操作要换规范」，这是最核心的一个问题；「开卡、囤卡、升级、退卡」放在核心工作里，因为它们是被改造的对象，不是问题本身。
- 流程本身是一致的，所以写「按卡种自动适配」，不写成「合并四套流程」。
- 成果只留实测的升级时长；折扣与退费「全程留痕」是定性交付结果，不编造提速幅度。

### PACS 影像读片与 AI 辅助｜AI 方案负责人｜2024.06–2025.06

```
项目背景：系统可以提示是否拍片，却无法记录医生是否完成读片，讲解过程也不留痕迹，
管理人员因此无法跟进这项日常医疗工作的落实情况。

核心工作：将依赖口头讲解的阅片过程重构为可记录、可追踪的流程，医生讲片时直接在影像
上标记并填写判断，内容随检查表同步至病历，无需二次录入；AI 只提供异常线索，是否
采纳由医生判断。

项目成果：已上线，2024 年 10 月至 2026 年 8 月累计读片 14.78 万张，读片完成率已成为
公司医疗质量复盘的指标之一。
```

**说明**
- 按规范三段式重写，约 145 字。
- 背景写「管理无从跟进」，不是「阅片耗时长」：后者是引入 AI 的动机，不是项目要解决的问题（`docs/pages/pacs-ai/content.md` §02）。
- 「AI 仅提供线索，由医生复核」保留：这是 AI 产品必须交代的边界，避免被追问准确率。
- 不写 96.3% 的 AI 参与比例（易被读成准确率），不写 60% 完成率（是目标，不是结果）。
